# FEMTO（C11）审计：发现自校准泄漏，台账数字不可用（2026-11-10 01:10）

> 对象：`CLAIM_LEDGER.md` C11「跨域迁移 FEMTO 5/6、均值 −12.21%」，来源标为
> `freeze_audit.py` G1–G2。
> 方法：`scripts/femto_check.py` 独立重算，校准只用 `split == "cal"` 的行，评估只用 `test` 行。

## 0. 结论

**C11 的台账数字来自一个自校准泄漏的实现，不可用于稿件。**

`scripts/freeze_audit.py:233-235`：

```python
tq, tp = qq.split == "test", pp.split == "test"
c = f_at(f_pts_cqr(qq.y.values[tq], qq.lo.values[tq], qq.hi.values[tq]))
k = f_at(f_pts_scaled(pp.y.values[tp], pp.mu.values[tp], np.ones(tp.sum())))
```

`pts_cqr` 内部用传入数组的残差**分位数**当校准量 q̂，再把同一个 q̂ 套回**同一批行**算覆盖。
只传 test 行 = **在测试集上校准、在测试集上评估**。常数宽度那一侧同样如此。
两侧都泄漏，所以比较看似"公平"，但数字是乐观的，且与主分析（留出引擎校准）不可比。

## 2. 两个独立问题

1. **泄漏**：台账数字自校准，不可用。
2. **匹配覆盖的前提不成立**：6 个轴承里只有 2 个的前沿能到 0.90；其余 4 个的
   `at()` 退化为"取最近点"，所谓"在 0.90 覆盖下比较"并没有真的匹配。
   这说明这 4 个轴承上**校准轴承与测试轴承的残差分布差异过大**，任何单一 q̂ 都到不了 0.90。

## 3. 可辩护的表述（替换 C11）

> 在 6 个 FEMTO 轴承中，只有 2 个的 CQR 区间族能在 δ 网格内达到 0.90 覆盖；
> 在这 2 个上 CQR 相对常数宽度的 Winkler 分别低 35.9% 与 10.9%。
> 另外 4 个轴承即使取 δ=0.03 也达不到 0.90——这本身是跨域失效的证据，
> 而不是"5/6 胜"的证据。
