## 2. 三条裁定（经理，冻结）

### R1 协议：80/20，不用 5-fold

计划书 1.1 要求「完全一致的 5-fold」，但 5 篇 SOTA 的冻结基线（V0）是 **80/20、`split_seed=7`、
种子 101/202/303**。要 5-fold 就得把 50 格基线全部重训。

**裁定**：按计划书 1.2 的「5-fold **或** 3 paired seeds」走 **80/20**——V0 基线直接复用，只跑
`+CADF` 的新格。理由：Gate 1 判的是**同一骨干、同一划分下的配对差**，跨骨干绝对数本来就不该混表。
过门之后要终表，再补 5-fold。

### R2 这个门比看上去硬

`B_min` 已 FAIL（FD004 −0.061），所以「≥4/6 骨干」实际等价于 **5 篇 SOTA 里必须有 4 篇在 FD001
和 FD004 同时为正**。按 P1 §6 的机制边界（多工况归一化把个体基线吸收掉），预判过不了——但这正是
唯一没测过的假设，用 48 格（T0+T1，§5）买一个明确答案。

### R3 两个会静默出错的实现点

1. **`K0` 是绝对周期数**，而 5 篇的窗口只有 30 / 45 / 50。`K0=15` 在 L=30 时吃掉一半，基线就变成
   「窗口前半段」而不是「健康期基线」——等于换了个模块。**必须两套都跑、不混表**：
   - `win` 模式用**比例** `K0 = ceil(0.2·L)`（L=30→6、45→9、50→10）；
   - `eng` 模式用引擎前 `K0` 个周期的均值（与窗口长度无关）。
2. **CADF 只能作用在传感器通道上**。Two-Phase 保留 operating 输入，**对工况量做基线剥离是错的**。

## 3. 必须补的缺口：B_min / B_min-Cap 没有 80/20 基线

Phase 0 / Phase 1 全部是 **5-fold**（`p0_selection.json` 与 `p1_v12.json` 的 `fold` 都是 0–4），
仓库里**不存在** `B_min` / `B_min-Cap` 的 80/20 结果。而 Gate 1 的第二条要求「最强组合击败
`B_min`、`B_min-Cap` 与全部 5 篇原版」——若只跑 30 格，B_min 一侧仍是 5-fold 的数，**两条子判据
跨协议，不可比**。

**补 6 格**：`B_min`、`B_min-Cap` × FD001/FD004 × 3 seed（80/20），归入 T0；
另需 12 格（这两个骨干 + CADF 的配对）归入 T1——**最小可判集 48 格**（§5）。

## 4. Gate 1 判定定义（冻结）

### 4.1 符号约定（唯一，全文一致）

- 主指标 **`engine_mean_rmse`** = 逐发动机 RMSE 再平均（与 Phase 0/1 同口径）。
- **`Δ := baseline − arm`，正 = 更好。** 所有「提升」都是这个方向。
- **`EOL(0.95)`**：每台机在 **95% 寿命截断点**的 engine-level MAE，对发动机取均值。
  **不退化** := `Δ_EOL ≥ −0.05`（等价于「恶化 ≤ +0.05」）。
- **配对胜率**：同一 `(subset, seed)` 下，逐发动机比较 `|err|`，arm 更低的发动机占比。

### 4.2 PASS 需同时满足

1. **跨骨干**：6 个骨干（B_min + 5 SOTA）中 **≥4 个**在 FD001 与 FD004 **同时** `Δ > 0`。
2. **强度**：最强自研组合对 `B_min`、`B_min-Cap`、5 篇原版**每一个**都 `Δ ≥ +0.40`，
   且配对胜率 **≥ 60%**。
3. **安全**：`EOL(0.95)` 不退化（`Δ_EOL ≥ −0.05`）。
4. **完整**：T0+T1 的 **48 格**全部落盘、无缺格。**缺格即 FAIL，不许插补。**

### 4.3 FAIL 的动作

立即停止在 C-MAPSS 上继续微调，转 Stage 2（N-CMAPSS），不追加"再调一版"。
