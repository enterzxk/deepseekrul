## 0. 铁律（从 CADF 那轮换来的；违反任一条不得开跑）

**铁律 0 · 信息来源，两问都要答，且都要有证据。**

1. **目标信息在输入里存在吗？** 若存在且可算，模块就只是在**重编码**——骨干内部能等价算出，模块注定只帮到
   「算不出这条变换」的小模型。CADF 的结局就是这么来的：`b` 是 `(x, cluster, mask)` 的确定性函数。
2. **骨干能内部算出等价变换吗？** 这一问靠**置换对照**回答，不靠论证。

**准确表述**（比上一轮那句「必须引入 `x` 之外的信息」更严）：模块输出**必然**是输入的确定性函数；
关键不是「输出是否由输入决定」，而是**「它利用的信息在输入里是否以可用形式存在」**。
- CADF：第 1 问**不过**（`b` 可从 `x` 精确算出）。
- ST-CCMR：第 1 问**过**（缺失/卡死通道的**真值不在输入里**，只能靠训练分布里的跨通道冗余去估计）；
  第 2 问由 §5 的置换对照回答。

**铁律 1 · 每个门必须配 MDE 与 `required_n`，且 MDE 必须在该条件下实测。**
不得拿别的条件下的 SD 代替。CADF 那轮的根因就是门槛设定时没做功效分析；同一个错误不许重演。

**铁律 2 · 置换对照是第二道门，不是第一道。** 顺序固定：先赢**强基线**，再赢**置换版**。
反过来会得到一个「打赢了自己的噪声、却没赢过线性回归」的假阳性。

**铁律 3 · 判据分支三分法**（`P2_CROSS_ARCH_PREREG.md` 补遗 #3）：
结构不可达（须附证明）／本批无实例（不得写不可达）／死文本（删掉）。三条不许混写。

**铁律 4 · 判定由记录逐字段生成**，禁止手抄。模板见 `paper_c/make_final_decision.py`（CADF 那轮的实现）。

## 1. 条件定义（**必须先冻结生成器，再谈门**）

四个注入条件，两个主条件（设门）、两个附表条件（不设门）：

| 条件 | 定义 | 是否设增益门 |
|---|---|---|
| `clean` | 不注入 | 只设**无害门** |
| `drop20` | 随机丢弃 20% 通道 | 附表，不设门 |
| `drop40` | 随机丢弃 40% 通道 | **主条件，设门** |
| `stuck2` | 2 个通道卡死在窗口首值 | 附表，不设门 |
| `stuck4` | 4 个通道卡死在窗口首值 | 主条件，**不设增益门**（§2、§5） |

**冻结前必须写死（现在还没写死，是缺口）**：

1. `drop40` 的**粒度**：逐元素 Bernoulli(0.4)／逐通道整段丢弃／逐窗口按通道比例——三者是**三个不同的问题**，
   `MaskAug`（B4）的增强分布必须与它**同分布**，否则「模块 vs MaskAug」比较的不是同一件事（牢莫 2026-11-23）。
2. 注入**掩码与位置由固定种子生成，且所有臂共用同一批受损窗口**（配对）。两臂注入不同样本，Δ 就是假的。
3. `stuck` 场景下掩码是**已知**（给模块）还是**需自动检测**（不给）。两种设定分开报，不得混。

## 2. 门槛与功效（**MDE 一栏是待填项，不是结论**）

公式：`MDE80 = 2.80 × SD(逐发动机配对 Δ) / √n`，`required_n = (2.80 × SD / 门)²`。

| 子集 | 可用验证引擎 n | 门（相对最强基线） | 能测出该门所需的 SD 上限 |
|---|---:|---:|---:|
| FD004 | 50 | **+1.5 RMSE** | `SD ≤ 1.5×√50/2.8 = 3.79` |
| FD001 | 20 | **不设增益门** | `SD ≤ 1.5×√20/2.8 = 2.40`（超出即测不出） |

**为什么 FD001 不设门（事前决定，不是事后找理由）**：20 台上要检出 1.5，SD 必须 ≤ **2.40**；
B 段 30 格实测的逐发动机 `SD(d)` 是 FD001 **1.86–3.52**（FD004 1.66–2.86），按 `required_n(1.5)` 算
FD001 **12–43**、FD004 **10–29**。所以 FD001 的 5 个骨干里**只有 1 个**（`dual_mixer`，SD 1.86）能在 20 台上
检出 1.5，其余 4 个都测不出——不足以支撑一个跨骨干的门。FD001 只要求**方向一致 + 不退化**。

**「有空间」与「测得出」同时满足的位置（zxk 2026-11-23 实测）**：`FD004 drop40` 经最强基线修复后残差
**5.29–7.40**（门 1.5 占残差 20%–28%），5 个骨干的 `required_n(1.5)` 都 ≤ 29 ≤ 50 → **全部可测**；
`FD001 drop40` 残差更大（2.49–4.33），但只有 1 个骨干可测（见上）；`FD004 stuck4` 残差只剩 **1.42–2.39**，
`+0.5` 的门**低于 `MDE`（0.65–1.14）** → 门本身不可测。
**所以跨骨干的主战场只有 `FD004 drop40` 一处**；`stuck4` 降为「不退化 + 方向一致」，`+0.5` 只作报告目标。
**门低于 `MDE` 等于没门**——这是铁律 1 的第一个实例，不是例外。

**MDE 必须在 Stage 0 实测后填**：这里要用的 SD 是**受损条件下**两臂配对 Δ 的 SD，B 段那个 SD 是 `clean` 条件下的，
**不能直接搬**（这正是 CADF 那轮「拿别的条件的数当依据」的同一类错误）。草案暂不填数。

**`clean` 无害门的口径（经理 2026-11-23 定）**：`|Δ̄_clean| ≤ 0.15` **且** 95% CI 含 0，两条都满足才算无害。
**但必须同时写明它的能力上限**：`MDE` 实测 **0.65–2.15**（B 段 10 格）远大于 0.15，所以「CI 含 0」这一条几乎自动成立，
这条门只能证明「**在现有功效下没测出有害**」，**不能**写成「无害」或「无影响」。

## 3. 四强基线（必须全部打赢；缺一不得宣称有效）

| 编号 | 基线 | 为什么必须在 |
|---|---|---|
| **B1** | `V0 + Global-Ridge` | 探针实测中位回收 **87%**（区间 47.2%–107.8%），不训练、闭式 |
| **B2** | `V0 + Cluster-Ridge` | 防止「分簇线性」就够；按工况簇分别拟合 |
| **B3** | `V0 + MLP-Imputer` | 同参数量级的**瞬时非线性**插补，隔离「非线性」与「时序」两个因素 |
| **B4** | `V0 + MaskAug` | 骨干训练期加同分布随机掩蔽——增益可能只是「骨干没见过损坏」，不是模块（zxk 2026-11-23） |

**B2/B3/B4 的协议要求**：折外（按**发动机**切，不得在同一批窗上拟合又评估）；B4 的掩蔽分布必须与 §1 的
`drop40` 同分布；B1/B2 的 α 不调（调了只会更强，门只会更高，方向安全）。

## 4. Stage 0（0.5 天，门是硬的）与止损

只在 `fcstgnn` × `{FD001, FD004}` × `{101,202,303}` 上，零训练或单次重训：

1. `V0 + Cluster-Ridge` 在 `FD004 drop40 / stuck4` 上比 `Global-Ridge` 多回收多少；
2. `V0 + MaskAug`（训练期随机掩蔽重训 1 个骨干）在同样两条件上的真实表现。

**止损（按计划书原文，并补上原文的空缺）**——记 `R` = `drop40` 上经最强基线修复后**距 `clean` 的残差**：

| `R` | 处置 |
|---|---|
| `R < 1.5` | **立即停机**，该方向终止（空间已小于门本身） |
| `1.5 ≤ R < 2.5` | **终止**（原文未定义此带；事前按保守方向补：留不出 1.0 的余量，模块无处施展） |
| `R ≥ 2.5` | 冻结预注册，进入 Stage 1 |

> 这条「灰带」是计划书的空缺，**在看到数据之前**补齐，方向取保守。经理可否决，但否决必须发生在 Stage 0 开跑前。

**Stage 0 的产物必须包含**：四个条件下的 `SD(配对 Δ)` 与 `MDE80`（填 §2）、`required_n`、
`MaskAug` 的掩蔽分布与 `drop40` 的逐项对照、以及「B4 是否已把残差压到 `R < 2.5`」的判定。

**Gate 1-Pilot（必须全部满足）**：

   `+0.5` 只作报告目标，**不进门**（理由见 §2）；

**结构对称性说明（与 CADF 那轮的区别，必须写进论文）**：CADF 的缺口是「唯一过线的格在分档里无处安放」——

## 6. Stage 2 / Stage 3

**Stage 2（C-MAPSS 跨 5 SOTA）**：6 骨干 × `{FD001, FD004}` × 3 seeds × `{clean, drop40, stuck4}` × 五臂。
Gate 2：**≥ 4/5 篇 SOTA** 上，`drop40` 相对**最强基线**（`max(Cluster-Ridge, MaskAug, MLP-Imputer)`）
满足 `3/3` 同号、`Δ ≥ +1.5`、发动机配对胜率 `≥ 70%`、engine bootstrap 95% CI 不含 0；
`clean` 过无害门。过门后补 `FD002/FD003`（不碰 `test`）。

**Stage 3（N-CMAPSS，池化 N=24）**：四个子集合并，`N = 24` 台独立引擎。
**池化前必须做的一步（草案新增，防口径混用）**：各子集的基线 RMSE 量级不同（DS02/05/06/07 各 6 台），
**不得直接平均原始 RMSE 差**；先把每台引擎的 Δ 除以**该子集的 clean RMSE**（或该子集 SD）再池化，
并**分表报各子集描述性均值**。否则池化值会被量级最大的子集主导。
Gate 3：`drop40` 上相对最强基线 `≥ +1.5 RMSE`（或 `≥ 15%` 残差回收）、胜率 `≥ 75%`、池化 CI 不含 0、
`clean` 退化 `≤ 2%`。
