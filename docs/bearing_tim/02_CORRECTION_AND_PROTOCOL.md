## 2. 发现的协议缺陷（比更正更严重）

`scripts/run_bearing.py`（v1）的早停用的是**留出轴承的测试 RMSE**：

```python
p = model(torch.from_numpy(xte).to(device)).cpu().numpy() * scale
rmse = float(np.sqrt(np.mean((p - yte) ** 2)))
if rmse < best: best, best_ep = rmse, ep      # <-- 用留出轴承选 checkpoint
```

**这是选择泄漏。** 首轮 18 次与扩展 22 次（共 40 次）都受影响，
因此它们**不能用于任何机制或性能主张**。用户任务一要求的
"训练、早停验证与评价轴承互斥"正是这一点。

## 3. 修正后的协议（v2，`scripts/run_bearing2.py`）

- **三重互斥**：留出轴承（评价）/ ES 轴承（早停）/ 训练轴承。
  每个 LOBO 折从剩余 16 台中再留 1 台作 ES（按寿命中位数确定性选取），训练用其余 15 台。
- 归一化统计量只来自训练轴承。
- 评价点：最后 15%（原指标）+ **固定寿命阶段 50%/70%/85%/95%**。
  寿命比例只用于**定位**评价点，模型输入只有该点之前 20 个快照的窗口。
- 波形按 `--ds` 做盒式平均降采样（默认 8）；抗混叠影响作为独立变量（ds=4/8）分析。

## 4. 归因臂（回答"C 的收益来自哪里"）

| 臂 | 编码器 | 融合方式 |
|---|---|---|
| **A** | 共享 CNN（双通道过同一编码器） | 拼接 + 线性 |
| **C** | 双编码器 | 拼接 + 线性 + **学习式乘性门控** |
| **C-Fixed** | 双编码器 | 拼接 + 线性 + **固定 0.5**（无门控） |
| **C-MLP** | 双编码器 | **等容量 MLP 融合**（无乘性门控） |

四个臂共享：输入波形、归一化、窗口、训练预算、随机种子、评价点。
**判据**：C 若与 C-Fixed/C-MLP 无显著差异，则收益来自双编码器或容量，不是门控。
