## 4. 结论

**`PIVOT`（弱读法）。**

**不是 GO**：本轮**无候选**。GO 要求的四件（优于强 DSPT、可解释、可复现、有新颖性的增量）**一件都没有**。

**与 STOP 的关系必须摊开写，不能靠辩解抹平。** 上一版这里写过「STOP 后半句不成立，因为本轮给出了一个可证伪的候选方向」——
**那句是错的，已撤回**：**它把「新机制」偷换成了「候选方向」**。STOP 的原文是「也没有**可靠新机制**」，
而本轮**恰恰没有新机制**（`无候选` 是 L2 的裁定）。**一个可证伪的问题不是机制。**

### 4.1 两条标签的条件逐条核

**STOP 条件**：

| 条件（用户原文） | 本轮 | 依据 |
|---|---|---|
| 「无法证明网络结构的核心贡献」 | **成立** | `0/4` 子集可区分（cycle 通道）、`0/28`（MS/SA/HI）、B-4 全 `undecidable` |
| 「也没有可靠新机制」 | **成立** | **L2 裁定「无候选」**（`PREREGISTRATION.md` §7） |

**→ STOP 的两个条件按字面都成立。**

**PIVOT 条件**：

| 条件（用户原文） | 本轮 | 依据 |
|---|---|---|
| 「找到新的研究问题」 | **成立** | `PIVOT_QUESTION.md`，含 `F1–F5` 失败条件、四项对照、三探针 |
| 「经过证实」 | **按弱读法成立** | §5.3 的结构性论证 |
| 「当前候选未解决」 | **不适用** | **本轮没有候选** |

**→ PIVOT 靠弱读法成立，且第三个条件不适用（不是「满足」，是「无对象」）。**

### 4.2 所以差别不在「条件满足度」，在「产出形态」

**两者是重叠的，不是互斥的**：

```
PIVOT 规定「重新提出单一科学假设」                     ← 我们交付的是 PIVOT_QUESTION
STOP  规定「转向新的研究问题 或 重新评估投稿定位」      ← 两条里我们落在前者
```

**结论：选 `PIVOT`，因为它的产出形态与本轮实际交付一致。**
**但必须同时写明：STOP 的两条条件按字面同样成立。这不是「STOP 被排除」，而是「两者重叠、我们选了产出更贴切的那个」。**

**⚠ 这样写的代价与收益**：代价是承认「本轮同时满足 STOP 的字面条件」；
收益是读者**不会被误导成「我们已经有了新机制」**——而这正是上一版那句辩解会造成的误读。

**本轮没有产生任何新的训练结果**：全部结论建立在已有 run 的重算之上（去重后 `96 run / 17040 点`）。

## 5. 为什么是 PIVOT 而不是 STOP（正面回答「经过证实」）

### 5.1 「经过证实」在这里指什么

**指：问题在已核范围内被确认为「尚未被覆盖」。不指「已证实有 headroom」。**

| 读法 | 内容 | 本轮是否成立 |
|---|---|---|
| **强读法** | 已证实该问题**存在 headroom**（存在可被拿到的预测增益） | **否**——本轮没有任何留出实验 |
| **弱读法（本文采用）** | 已证实该问题在**已核范围内尚未被覆盖** | **是**（见 §5.2） |

### 5.2 弱读法成立的依据（逐条可核）

**① P_a 已被现有实现覆盖——这是「问题被切小」的证据，不是「问题被解决」的证据。**

`data.py:146 _baseline_ref` 已做七件事：`cycles<=30`、`clusters==cl`、`arange<=t`、`early[-5:]`、`TAU=2.0`（`:23`）、
`pop_ref` 取训练机 `cycle<=15`（`:268/:271`）、无 lifetime 字段；`dspt.py:152` 输入已是 `[x, x−baseline, causal EMA]`。
**所以「前缀有用」这个命题已经被吃掉了。**

**② P_b 在已核范围内未被覆盖。**

`PREFIXCAL_NOVELTY_REVIEW_20261114.md` 核了三篇近邻（Ensarioğlu 2023 §2.4、Robinson 2026 §4.1.1、DAIN §II）与仓库内部实现，
结论是**朴素前缀扣均值不具新颖性**——因为它们覆盖的都是 **P_a 型**机制。
**在已核范围内，没有工作把「个体前缀」放在「一个已经用了个体早期基线的系统之上」再问增量。**

**⚠ 这条是范围限定的，不是全称否定**：**不能说「P_b 无人做过」**，只能说「**在已核的三篇近邻与仓库代码中未发现覆盖**」。
该审查文件 §8 自标边界：三篇原文由军师核、牢莫未复读，**不声称「两人读过原文」**。

**③ 问题可证伪——这是「问题成立」的最低要求，已满足。**

`PIVOT_QUESTION.md` §4 给出 `F1–F5` 五条失败条件（任一条成立即判失败），并给出四项对照与三个机制探针。
**一个能被判死的问题，才是一个研究问题。**

### 5.3 为什么弱读法足以支撑 PIVOT

用户原文：「找到新的、**经过证实**的研究问题，但**当前候选未解决**」。

- **「当前候选未解决」**：完全成立——本轮**无候选**。
- **「新的」**：成立——P_b 与 P_a 是可分离的两个命题（`PIVOT_QUESTION.md` §1 有对照表），而 P_a 已被覆盖。
- **「经过证实的研究问题」**：**按弱读法成立**——问题在已核范围内确认为开放，且已写成可证伪形式。

**关键**：PIVOT 要求证实的是「**研究问题**」，不是「**研究结论**」。
若要求后者，那就变成了 GO 的门槛，而 GO 已被「无候选」否掉。
**把 PIVOT 的「经过证实」读成「已证实有 headroom」，等于把 PIVOT 变成 GO 的弱化版，这一格将永远无法达成。**

### 5.4 若 L2 不接受此读法

**翻成 `STOP`，而问题不丢。**

```
标签改为 STOP
产出仍是 PIVOT_QUESTION.md（作为 STOP 定义里「转向新的研究问题」的产出）
差别只在一句话：是「已证实的问题」还是「待验证的问题」
```

**这个切换不损失任何证据**：§2–§3 全部照用，§4 只改标签与理由。
**两种读法都不允许第三种写法——把「定义清楚」当成「已证实」。**
