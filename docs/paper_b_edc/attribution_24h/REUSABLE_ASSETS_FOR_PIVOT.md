# PIVOT 问题的可复用资产索引

用途：给阶段五的 `PIVOT_QUESTION.md` 配一份资产台账，标明**哪些现成材料能直接支撑**、**哪些不能**。
只读核对，未改动任何实验产物；所有数字都能从列出的文件重算。

---

## 0. 一句话结论

**四个池子全部建在同一批验证发动机上（`20/52/20/50`），没有任何"未见发动机"留出。**
所以 PIVOT 问题的第一个实验前提——**发动机分组留出**——**现有资产一条都支撑不了，必须新建**。
`val_pred` 池只能支撑"同引擎上的误差结构诊断"，不能支撑任何泛化声明。

```

V0N 12 格 = 3 seed × (100+260+100+250) = 2130
```

**去重规则（必须写在索引里，否则会重复计数）**

## 2. 能支撑什么（逐条对应 PIVOT 问题）

| PIVOT 要回答的子问题 | 现有资产能不能 | 说明 |
|---|---|---|
| 同引擎上"误差与早期前缀特征是否相关" | **能（诊断级）** | 96 格逐点预测 + A0 预测；但这是**样本内相关**，不是增益 |
| 封顶区 / 退化区分开报误差 | **能** | `y_true==125` 可直接从 `y_true` 切 |
| 按工况簇分组的误差 | **能（需工况定义）** | FD001/3 单工况、FD002/4 多工况；工况定义要先冻结 |
| 同一 `cycle` 箱内跨发动机离散度 | **能** | `cycle` 列在 A0 `preds.csv` 里；A8 的 `val_pred.csv` 需从 `cut`/窗口反推，见 §4 |
| **未见发动机上的前缀增益** | **不能** | 见 §3——没有任何留出引擎 |
| **"在 `_baseline_ref` 之外"的增量** | **不能** | 需要重训（关掉/替换 `_baseline_ref` 的对照臂），现有池子没有这个臂 |
| 不优于同信息简单替代（收缩基线 / 普通中心化 / M2 / 等参数） | **不能** | 同上前提：需要新臂；现有只有 vanilla / M2 历史格，且不同协议 |

## 3. 为什么"不能"：同一批引擎，零留出

实测（3090，逐 run 比对 `val_pred.csv` 的 `unit` 集合）：

```
A8_base_L70/FD001/s101    units=20
A8_full_L70/FD001/s202    units=20
F_single_proj_basic_hi1/FD001/s303 units=20
V0N_L70/FD001/s303        units=20        → FD001 all_equal True (4 组比对)
A8_base_L70/FD002/s101    units=52
V0N_L70/FD002/s202        units=52        → FD002 all_equal True
A8_ms_L70/FD004/s101      units=50
V0N_L70/FD004/s101        units=50        → FD004 all_equal True
```

**同一子集内，臂与 seed 之间的验证引擎集合完全相同**（`split_seed=7, fold=0, val_frac=0.2` 冻结）。
所以：

1. **任何在这些池子上拟合的前缀模型都是样本内的**——包括"留一发动机"这种半留出，也只是同一批引擎的重复切分，**换不出新引擎**。
2. **唯一的"未见发动机"是官方 test 集**（`100/260/100/249` 台，与验证引擎不相交）。但按本轮规则，**test 只作描述、不作选择依据**，**不能用来验证新机制**；用它筛 PrefixCal 就等于二次开封。
3. 所以 PIVOT 的验证必须**新造一个发动机分组留出**：从**训练侧**引擎里切（FD001/3 各 80、FD002 208、FD004 199 台可用），**并且要在预注册里冻结切法**——换切法就是换协议。

**这条必须写进 `PIVOT_QUESTION.md` 的"所需数据"**，否则下一轮会以为可以拿现有 96 格直接开跑。

## 4. 两个 schema 细节（决定分析做不做得成）

| 资产 | 有 `cycle` 吗 | 有 `engine_id` 吗 | 备注 |
|---|---|---|---|
| A8 / V0N `val_pred.csv` | **没有显式列** | 有（`unit`） | 年龄需从窗口/`cut` 反推；**不能直接按 `cycle` 分箱**，要么补 `cycle` 列（改产物，需声明），要么用 `cut` 近似 |
| A0 `preds.csv` | **有**（`cycle` 列） | 有（`engine_id`） | 但只有 4 格、n=1，且是 Age-only |

**所以"同一 cycle 箱内跨发动机离散度"这一问，在 A8 池子上不能直接算**——需要先解决 `cycle` 从窗口反推的口径（并写清反推规则），否则箱边界不可复现。

## 5. 若要跑 PIVOT：最小新建清单

| 需要的东西 | 现状 | 说明 |
|---|---|---|
| 发动机分组留出切法 | **无** | 从训练侧引擎切；须在预注册冻结（哪些引擎进 fit、哪些进 holdout、每个子集多少台） |
| 关掉/替换 `_baseline_ref` 的对照臂 | **无** | 这是"之外"命题的核心对照，缺它就只能证明"前缀有用"，而这一点上一轮已被否 |
| 同信息简单替代（收缩基线 / 普通中心化 / M2 / 等参数） | 部分有（M2 历史格，协议不同） | 需按同一协议重跑，不能跨协议借数 |
| 门槛与失败条件 | 预注册骨架已冻结（`val_engine_mean_rmse`、`df=n−1`、精确 `t`、同号 3/3） | **必须在开跑前冻结，跑完不改** |

**结论**：现有资产能支撑**诊断与描述**（误差结构、封顶区、工况分组），**不能支撑任何"未见发动机"的泛化或增量声明**。
PIVOT 问题的可证伪形式必须自带"新留出 + 新对照臂"这两件东西，否则它只是把上一轮被否的命题换个说法。
