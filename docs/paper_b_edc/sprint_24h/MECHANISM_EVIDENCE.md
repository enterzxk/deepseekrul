# 机制证据台账（MECHANISM_EVIDENCE）

> 只收**已实测**的机制事实，每条带证据路径与口径。推测必须标注「推测」。
> 判定：机制证据 ≠ 性能收益。性能只认 `MODULE_RESULTS.csv` / `SEED_RESULTS.csv`。

## 已确认（可复算）

### E1 · 零初始化残差头在第 0 步精确等于先验

`max|pred − prior| = 0.000e+00`。说明 AAR 的起点确实就是 AGE 先验，优化器第一步只动输出层。
证据：`1fea746`；3090 `HC-D-AAR-FD001-s101`。
用途：证明 AAR 的"残差"定义成立；也是 F1 起步慢（每 epoch 0.11–0.23）的结构原因。

### E2 · AGE（无参数纯先验）跨机逐位一致

`30.585567807510262` 在 a40（cudnn9/cu124）与 3090（cudnn8/cu121）**完全相同**。
证据：`HC-D-AGE-FD001-s101`。
用途：无参数臂走完全相同的 data + evaluator，所以 B0 的 **4.9% 跨机差**只能来自**模型数值路径**，不是数据或评估器。论文环境说明可直接引用。

### E3 · 封顶窗不是被 cap 掩盖，而是误差更大

B0-FD001：`cens = 15.961` vs `uncens = 13.082`，同时 `boundary_hit = 0.000`。
用途：capped 与 uncapped 两层必须并排读；`boundary_hit = 0` 说明当时预测还没顶到 125，误差是真实差距而不是截断假象。

### E4 · M4（CSR）通过发车前三条闸（3090 实测）

```
PASS  transparent_at_step0          max|diff| = 0.000e+00
PASS  bias_is_the_only_difference   moved = 7.069e-03, restored = 0.000e+00
PASS  reliability_weights_are_live  mean(max-min w) = 2.279e-01
CONTRACT OK  (3/3)
```

- **透明性**：零初始化偏置下 M4 与 B0 逐位相同（`0.000e+00`），所以 B0→M4 的差值不是重新初始化带来的。
- **偏置是唯一差异**：改动偏置预测会动（7.069e-03），清零后精确回到 B0（`0.000e+00`）。
- **不是恒等映射**：可靠性权重在传感器间有实际分散（2.279e-01），说明模块是活的、不是死代码。
- **归因边界（必须写明）**：M4 只加 `cond_bias`，**6×14 = 84 个参数**，而 B0 的可训练参数是 **115 010**，所以只占 **0.073%**（不是 7.7 万那个旧口径下的 0.1%），「容量增加」不构成混杂；`trend_proj` 只在 `csr_mode='full'` 时构造，**本轮 M4 是 M4-C（condition-only），不是 M4-D**。
- **归因成立 ≠ 机制成立**：差值可归因到「工况可靠性加权」这一处，但是否真吃到传感器，仍要过**同龄排序显著 > 0.5 且置换退化绝对量明显大于 B2 的 +0.45** 两条（探针口径见 E5 与下方待填表）。B0 的参照是 0.7699 / +24.6 绝对（+195%）。

## 已测但未判定

### E5a · SCR 的 D 分布：两个「无 SCR」臂互相矛盾，**不能并成一个结论**

| 臂 | 有无 SCR | 存活期 frac(D>1) | 越界发动机 | 罚项总量 |
|---|---|---:|---:|---:|
| 初始化（未训练） | — | 2.87% | 20 | 41.8 |
| **B2** | **无** | **12.46%**（60% 发动机，a40） | 48/80 | — |
| **B3** | **无** | **1.74%** | 7 | 8.37 |
| M7 | 有 | 1.57% | 7 | 6.81 |
| M3B | **无**（另一架构） | 1.57% | 8 | 6.97 |

- **两个「无 SCR」臂差 7 倍（12.46% 对 1.74%）**。所以「无约束时训练会不会自己把 D 压回 1 以下」**没有普适答案，取决于架构**。
- 因此：① 「训练自然满足约束」（解释 B）**在 B2 上被直接证伪**；② 「SCR 在压」（解释 A）**只能在同架构内比较**——B3 8.37 → M7 6.81（−19%）是目前唯一干净的证据。
- **禁止**把 B2 的 60% 和 B3 的 1.74% 混成一句「无 SCR 时越界严重」或「无 SCR 时也还好」。跨架构引用同一「无约束」标签，就是这一轮最容易犯的错。
- 结构性残留：同一批 5 台发动机（55/73/53/76/69）在 B3/M7/M3B 里都越界，说明这是结构问题而非训练随机性；最深的一台在失效前 78 个周期就已 D>1。
- **口径警告（2026-11-13 补）**：日志里的 `alive=` 是**单 batch 采样**，不是全训练集；而且 `alive` **没有进 `history.json` 的 `grad_terms`**（那里只有 `rul/terminal/smooth`），全精度值没有任何地方落盘。所以「80 个 epoch 里 78 个是 0」只能读作「**单 batch 采样下多数落在 0**」，**不能读作「约束零梯度」或「未激活」**。本表的 `frac(D>1)` 来自 **checkpoint 上的全训练集探针**，与此是两套口径，引用时必须分开写。要判「未触发」还是「被压住」，得先让 `alive` 进 `grad_terms` 并落盘。

### E5b · M7 vs B3 的 −0.77：单 seed 正向，**但机制幅度不支持**

- M7 13.92 对 B3 **14.69**（B3 `best_ep` 57、ep69 早停，**是真收敛值不是下界**），单 seed 好 0.77；M3B 13.58 好 1.11。
- **不能归给 SCR**：SCR 只作用在 **1.7%** 的存活周期上，罚项总量只降 **19%**（绝对值约 1.6 / 8800 的损失量级）。**一个这么小的机制不可能产生 0.77 的 RMSE 变化。**
- B3 自己的单 seed 波动未测，0.77 可能落在噪声内。
- 结论：**「单 seed 正向，未排除噪声」**，**不得写「消融有效」**。要定论需补 B3 的 s202/s303。
- 这与 B2 上遇到的是同一类问题：**数字好看，但说不出它是从哪来的**。

## 纪律

1. 机制指标必须**在训练集/验证集上按冻结协议**算，不得用 test 挑。
2. 传感器置换、同龄配对等探针若**落在训练分布外**（如 OOD 置换），只能说明敏感性，**不能当分解证据**（G4 的教训）。
3. 任何"HI 摆脱年龄计时器"的主张，必须给出**同龄发动机之间的可解释 HI 差异**，不能只给单调性——单调性由构造即可满足。
4. **作用面与效应量差两个数量级时，不许做因果归因**。判据：机制的作用面（占多少周期、把目标项降多少、该项占损失多大）与观察到的效应量（RMSE 差多少）不在同一量级，就只能写「单 seed 正向，未排除噪声」。例：SCR 只作用在 **1.7%** 的存活周期、罚项只降 **19%**（损失量级 1.6/8800），却对应 **0.77** 的 RMSE 差 → 不得归因。
5. **D / 约束类结论必须绑定母体**。对 **B3** 母体，约束主要是被满足的（2.87% → 1.74%）；对 **B2** 母体，约束有大量作用点（60% 发动机、12.5% 周期越界）。跨架构引用同一个「无约束」标签会得出相反结论。**M7 的母体是 B3，所以 M7 按「约束主要被满足」记。**
6. **校验必须走真实入口**。M4 的第一版闸直接构造 `DSPT_CSR`，3/3 通过，而真跑走 `build_d` 秒炸（`cycle_mode` 重复传参）。**闸门测私有构造路径等于没测**；任何发车前的检查都必须经过 runner 用的那条路径。
7. **记录必须可归因，否则等于没记**。与第 6 条同一类：`code_fingerprint` 只存了一个**聚合哈希**、`git_sha: None`、没有逐文件哈希，于是「B0 三 seed 是不是同一份代码」这个问题**无法在产物层面回答**，只能回 git 历史重建，而重建还碰到一个查无 commit 的指纹（`e89b23b0`，跑在未提交工作树上）。
   - 判据：**一条记录如果不能在产物层面回答它本来要回答的问题，它就不是证据，是噪声。**
   - 修法：`files` 列表旁直接存**逐文件哈希字典**；`alive` 这类判据量必须进 `grad_terms` 落盘，不能只留单 batch 日志。
   - 同源教训：M4 那次「6 条断言全过、真跑第 1 轮卡死」，也是「记了不该记的东西、没记该记的东西」。
