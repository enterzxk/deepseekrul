# Paper B / HC · 评测纪律（Eval Discipline）

最后更新：2026-11-12 03:50（a40 本地）
适用：Gate A / G1 / G2，以及后续所有涉及"训练耗时""效率""并发收益"的表述。

---

## 1. 规则：a40 上的墙钟时间不得作为指标

**禁止**在论文、报告、内部结论中用 a40 上测得的训练耗时支持以下任何一类陈述：

- 加速比 / 吞吐 / "A 比 B 快 N 倍"；
- 单格训练的绝对耗时当作方法复杂度证据；
- 并发 vs 串行的效率对比。

原因不是"不可复现"这么弱 —— 是**它连相对快慢都不成立**：同一份代码、同一个 seed、逐位相同的结果，墙钟可以差 4 倍。

---

## 2. 证据：同一配置六次运行

配置：A3p / FD001 / seed 101 / 同一 init / 同一 v9 锁。指标逐位相同。

| run_id | elapsed_s | val_engine_mean_rmse | 运行条件 |
|---|---|---|---|
| `HC-C-A3p-FD001-s101-20261112T0005Z` | 200.5 | 10.895096839289387 | 串行 |
| `HC-C-A3p-FD001-s101-20261112T0030Z` | 200.8 | 10.895096839289387 | 串行 |
| `HC-C-A3p-FD001-s101-W1` | 201.3 | 10.895096839289387 | 串行 |
| `HC-C-A3p-FD001-s101-20261111T1508Z` | 347.8 | 10.895096839289387 | 串行 |
| `HC-C-A3p-FD001-s101-R1-20261112T0035Z` | 811.0 | 10.895096839289387 | 串行 |
| `HC-C-A3p-FD001-s101-R3CONC2` | 954.7 | 10.895096839289387 | 2 路并发 |

- 串行内部摆动：200.8 → 811.0，**4.0×**。
- 并发那次 954.7 s 只比串行最慢一次高 18%，落在串行分布的外侧边缘。

**结论：「两路并发使同一格变慢 4.75×」不成立，已撤回。**

## 3. 已撤回结论（不得再引用）

> ~~两路并发使同一格变慢 4.75×（201 s → 954.7 s），吞吐只剩串行的 0.42 倍。~~

撤回理由见 §2：串行基线自身摆动 4.0×，954.7 s 无法归因于并发。

注意：郑总上一轮基于该数字把 3 路并发改回串行。**串行仍然可能是正确选择**（没有测到收益、OOM 风险、混条件），但**不能再用 4.75× 当证据**。

---

## 4. 仍然成立的并发结论

1. **并发不改变数值。** `R3CONC2` 与全部串行 run 的 `val_engine_mean_rmse` 逐位相同（10.895096839289387）。这对 G1 的 1.0% 阈值有意义：并发不会污染指标本身。
2. **并发没有测到吞吐收益。** 目前没有任何正向证据；默认串行。

## 5. 效率 / 成本应该报什么

- 参数量 `params`、`trainable_params` —— 已在 metrics 里。
- 前向 FLOPs —— 需补测一次，与主机负载无关。
- 峰值显存 —— device 侧 `torch.cuda.max_memory_allocated()`，与主机负载无关。
- 若必须报时间：换到空闲主机、固定协议（无其它训练进程、固定 batch、固定 epoch 数）、重复 ≥3 次取中位数，并声明主机空闲状态。

---

## 6. 共享机事实（用于解释波动）

a40 是共享机，同一时刻可能同时存在：

- `combined_queue`（baselines 匹配基线波次，`--budget-mib 36000 --workers 3`，队列 pending 60+）；
- 他人的 BPI 流程挖掘任务（`code/unified/train.py`、`code/audit/order_sensitivity.py`）；
- 常驻 `math_modeling`（约 678 MiB）、ComfyUI（约 262 MiB）。

`combined_queue` 起 worker 前会扣掉 `other_used_mib`（别的进程占的显存）再判 `other + reserved ≤ 36000`，所以**起格这一侧是互保的**；但已经在跑的进程不会因此让出算力。这正是同一格耗时能在 200–811 s 之间摆的原因。

## 7. 命名坑（读数据前必看）

同一概念在不同文件里有两个名字，取错键会拿到 `None` 而误以为数据缺失：

| 概念 | close.json | metrics.json |
|---|---|---|
| best epoch | `best_epoch` | `best_ep` |
| git 提交 | `git_sha` | `code_lock_git_sha` |
| 训练耗时 | 无此键 | `elapsed_s` |

v10 应统一键名；在此之前，任何脚本读这两类文件都要两个键都试。
