## 网格（含预注册对照臂 `N2s`）

**五档**：`N0` / `N1` / `N2` / **`N2s`** / `N3`。
`N2s` = `N2` + **第 1 批实际用过的那套切法**（`reshape(14,3)`，即统计量优先的残余分组），作为**声明式对照臂**预注册在此，
不因结果好坏增删。其余四档用逐传感器 tokenizer。

**对照能成立的前提是同参数**（`scripts/nc_param_check.py` 实测）：

| rung | params | token_layout | ms | sa |
|---|---:|---|---|---|
| N2 | 77,506 | sensor_major | off | off |
| **N2s** | **77,506** | statistic_major | off | off |
| N3 | 116,034 | sensor_major | full | basic |

N2 与 N2s **同参数量、同输入、同预算，只差 token 布局**——所以两者的差只能归因于切法，不能归因于容量。

**但 `N2s` 不是干净的「统计量分组」设计**：三组之间是错位的（均值覆盖传感器 1–12、标准差 2–13、斜率 3–14），
序列位置 j 在不同统计量下对应不同传感器。所以若 N2s 在六折上赢，**机制解释必须把这个错位算进去**，
否则会写出一个比实测更漂亮的机制。这一条已写进协议正文。


## 三条禁止

- **不按已开封的测试成绩选修法**。修复方案只依据协议与 dev 冻结。
