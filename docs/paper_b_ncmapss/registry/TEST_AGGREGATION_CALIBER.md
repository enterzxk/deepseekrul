# 测试批 20 个聚合列的「可断言性」标定

**回答一个问题**：测试行上那 20 个按机聚合的列，哪些行的值**在代数上必然**等于池化值？

答案不是靠比数值——是**数每台机在该聚合集合里贡献了几个飞行**。

## 为什么必须用计数

若每台机在该聚合集合里都贡献 `k` 个样本：

```
池化 = (Σ_e S_e) / (E·k) = (1/E) Σ_e (S_e / k) = 逐机等权
```

两种聚合**恒等**。所以这一行的这一列不携带「聚合口径」的任何信息，标 `pass` 是把
「不可能失败」写成「通过」。

数值比较分不开这件事和「碰巧相等」，而两者含义不同：

| 状态 | 判据 | 含义 |
|---|---|---|
| `degenerate` | 各机样本数**全部相同**（含只有一台机） | 代数恒等，**不可断言**，不是通过 |
| `pass` | 样本数不同、值也不同 | 真的通过 |
| `pass_coincident` | 样本数不同、值却相等 | 真的通过，但标出来，免得有人把「相等」读成「没有差别」 |

## 实测（80 行 × 20 列 = 1600 格）

```
pass 1360    degenerate 240    pass_coincident 0
```

退化**不在** `_unit` 列上，全部落在**绝对分段**的三列：

| 列 | 退化范围 | 原因 |
|---|---|---|
| `seg_late_absolute_*` | **80/80 行（四个子集全部）** | 该段是 RUL < 25，**恒为每机 25 个飞行**，与寿命无关 |
| `seg_mid_absolute_*` | DS07 的 20 行 | DS07 四台机寿命都 ≥ 75，各 50 个飞行 |
| `seg_early_absolute_*` | DS02 的 20 行 | 只有 unit 14 够到 RUL ≥ 75，`counts=[1]` |

8 个 `_unit` 列与 6 个 `*_relative` 列在 1600 格里**全部 `pass`**——各机飞行数不等，两种聚合确实不同。

## 两条被这张表纠正的说法

**① 「`n_units > 1` 就检查得到」是错的。** `seg_late_absolute_*` 在 4 台机的行上照样退化：
`counts=[25,25,25,25]`。判据是样本数相等，不是机数。

**② 经理举的那个 1.261「碰巧相等」不是巧合。** 那是 `DS02_N0_TEST_f200` 的
`seg_early_absolute_raw`，`counts=[1]`——**结构性退化**，不是巧合。所以
`pass_coincident` 目前**一次都没出现过**：这个状态存在是为了区分两种成因，
但到目前为止还没有观测到真的巧合。

## 对封存表的影响

封存的 80 行**数值不受影响**——逐机等权值本来就是对的，退化只意味着「在这一列上，
逐机等权与池化给出同一个数」。所以**不改已封表的任何字节**，这条标定作为独立的审计产物存在。
