## 1. 设计

四个注入位置，`DSPT` 强骨干（`ms_mode=full, sa_mode=basic, hi_source=hf, hi_mono=correct,
span=70, d_model=64, layers=2, dropout=0.2, mode=dual, aux_dual=True`，`epochs=40`，
`patience=12`，`batch=512`，`lr=1e-3`，`rul_cap=125`）：

| 位置 | 机制 | 实现 |
|---|---|---|
| `none` | 不加 Cycle（V0N 的 5 种子版） | `use_cycle=False` |
| `pre_norm` | `norm(pooled + pe_proj(pe))` | `dspt.py:259-261` |
| `post_norm` | `norm(pooled) + pe_proj(pe)` | `dspt.py:262-264` |
| `head_concat` | 不相加，8 维 PE 拼进回归头输入（`head_in = d_model + 8`） | `dspt.py:285-289` |

Cycle 定义（与预注册一致）：窗口最后时刻的当前累计运行周期，`cycle = min(c/250, 1)`，
Fourier 编码 `c_abs = cycle × 250`，周期 `(25, 50, 125, 250)`，输出 8 维
（`sin`/`cos` 各 4）。与 DSPT 原有的 `_cycle_pe` 是同一个函数。

规模：4 子集 × 4 位置 × 5 种子（101/202/303/42/43）= **80 格**。

精度：**全部 FP32**，禁 autocast/TF32，`cudnn.deterministic=True`、`benchmark=False`。
不与历史 BF16 结果混表——BF16 跨进程不可复现（同一份权重重跑 12 个 run 全漂移，FP32 下
最大差 1.12 周期）。

## 3. 指标口径

**engine-level RMSE**：先对每台发动机的 5 个固定截点（`round(f·n)`，f = 0.40/0.55/0.70/0.85/0.95）
算 RMSE，再对发动机等权平均。发动机是统计单位。

`metrics.json` 的 `val_engine_rmse` **禁用**：该字段名承诺 engine-level，实际存的是 pooled
（把同一台机的 5 个截点当独立样本）。两者不是小偏差——80 格上实测最大差 **6.1382**
（`S1A_none/FD004/s303`：pooled 19.7102 对 engine 13.5721；缺格阶段 7 格上为 1.4161）。
拿错字段可以直接翻转结论。

分析脚本在每次运行末尾打印这个最大差，作为该字段仍不可用的持续证据。

### 4.1 两列参数的定义

**总参数** = `sum(p.numel() for p in net.parameters())`，即优化器可见的参数。`requires_grad`
在 `dspt.py` 与 `train.py` 里没有任何 `False`，`AdamW` 接收 `net.parameters()`
（`train.py:119`），`metrics.json:params` 就是同一个 `sum(p.numel())`（`train.py:118`）。
所以模型创建的每个参数都在优化器里。

**有效参数** = 前向参与计算、因而有梯度通路的参数。`head_concat` 的 576 个 `pe_proj`
参数满足「总参数」却**不**满足「有效参数」：`pe_proj = Linear(8, d_model)` 在
`use_cycle=True` 时无条件创建（`dspt.py:129-130`），但 `head_concat` 走的是
`self._cycle_pe(cycle)` 直接拼进加宽的头（`dspt.py:285-289`），**从不调用 `pe_proj`**。
可检查：`grep -n "pe_proj" paper_b/models/dspt.py` 只有 130（创建）、260、264
（`pre_norm`/`post_norm`）三处。同一个位置在公开方法的插件上被梯度实测过：
`head_concat` 下 `pe_proj.weight.grad is None`，另两个位置有梯度
（`scripts/smoke_cycle_plugin.py`）。这 576 个参数占用优化器状态，但不贡献容量。

因此：`pre_norm`/`post_norm` 总 = 有效 = 115 651；`head_concat` 总 116 163、有效 115 587
（**+512 = 0.44%**，头输入从 64 加到 72：`72×64+64` 对 `64×64+64`）；`none` 115 075。

**容量门用有效参数**（0.44%），总参数（0.95%）同时列出。两者都低于 1% 门槛，因此不触发
「必须做容量匹配对照」，判定不变。

`metrics.json` 只记 `params`，没有 `trainable_params`；上表的「有效参数」不是从结果文件
读出来的，而是由上面的前向与梯度证据推出来的。

## 6. 边界与披露

- **`dual_mixer` 的妥协**：它用自己的对比损失（`compute_loss` + InfoNCE），联合训练会改它的
  目标函数，所以第二半只能冻结基座、只训头。这**不是**「架构无关插件」的完美实现，是已知
  实现妥协，正文不得省略。
- **官方 TEST 不参与选择**。胜出位置在计算任何 TEST 数字之前冻结；四个位置的 TEST 可在冻结后
  作描述性报告，不得据此改选。
- **缺格不插补**。任一位置在任一子集缺格或缺 seed → 该位置不具备 `Q` 资格，直到补齐；
  不得用 4 seed 近似 5 seed。
- **跨机时间戳先校准**：a40 的系统时钟比 3090 快 **8 分 53 秒**（实测 a40 18:22:26 对 3090
  18:13:33）。只有单格耗时可比，墙钟时刻不可比。日志的 `ep` 编号每格归零、且每 5 轮打一行
  （`train.py:173`），不得据日志行数推轮数或总轮数。
- **速率（实测，非外推）**：3090 侧 8.7–9.5 秒/轮（4 格 `elapsed_s/epochs_run`），a40 侧
  23.1 秒/轮（1 格）。a40 与三个外部训练任务共用同一张卡（load average ≈ 20），
  所以慢 2.6 倍。

## 8. 判定（按冻结件 `v1`）

`scripts/analyse_s1a.py` 的 `decision` 字段原文：

| 项 | 值 |
|---|---|
| `rule_version` | `v1` |
| `prereg_commit` | `29f337f9575877b59bd7ca1fcd6f0c84f516dcea` |
| `eligible` | `pre_norm`, `post_norm`, `head_concat` |
| `blocked` | 空（无缺格、无陈旧配置、无容量超限） |
| `qualified`（`Q`） | `pre_norm`, `post_norm`, `head_concat` |
| `winner` | **`null`** |
| `selected_position` | **`pre_norm`** |
| `fallback_used` | **`true`** |
| `cycle_is_negative_effect` | `false` |

**判定：无唯一胜出；第二阶段用 `pre_norm`，并明确记为「默认，不是证据」。**

触发的条款是「`|Q| ≥ 2` 时需成对支配」这一条：`Q` 有三个成员，`pre_norm` 的点估计最好，
但它没有对 `post_norm` 构成支配（`post_norm − pre_norm` 的 95% CI 含 0）。因此不满足唯一胜出，
按预注册回落默认值。

这一判定**不是**「三个位置一样好」，也不是「Cycle 没用」。三件独立的事要分开读：

1. **Cycle 本身有效**：三个位置对 `none` 的合并 95% CI 全部不含 0，方向 4/4 或 3/4，
   5/5 seed 同号。这是本阶段最强的结论，且不依赖位置选择。
2. **`pre_norm` 与 `post_norm` 分不开**：方向一致 4/4 但区间跨 0，是功效问题（每子集只有
   20–52 台验证机、5 个 seed）。要分开需要更多 seed 或更多发动机，本阶段不做。
3. **`head_concat` 可被排除**：`pre_norm` 对它 95% 与 98.33% CI 都不含 0，方向 0/4；
   它还在 FD001 上比 `none` 差。第二半不应该用它。

`cycle_is_negative_effect: false` 对应预注册里「`none` 是否对每个位置都显著更好」的反向检查，
未触发：没有任何位置在合并口径上显著劣于 `none`。

### 8.1 支配检验用的镜像区间

冻结件的合格条件是「合并 95% CI **上限 < 0**」，这要求以 `pre_norm` 为被检对象时把 §7.3 的
行**镜像**过来读，不能直接套用。两者都列出来，避免读者按 `head_concat − pre_norm` 那行误判：

| 被检对比（负 = `pre_norm` 更好） | 95% CI | 上限 < 0？ | 98.33% CI |
|---|---|---|---|
| `pre_norm − post_norm` | [−0.7303, **+0.1409**] | **否**（跨 0） | [−0.8134, +0.2494] |
| `pre_norm − head_concat` | [−0.9817, **−0.1420**] | **是** | [−1.0857, −0.0504] |

所以：`pre_norm` 支配 `head_concat`，但**不**支配 `post_norm`。支配要求对所有合格位置成立，
一条不成立即判无胜出。
