## 1. 精度事实（必须先读）

仓库里保存的 `val_pred.csv` / `test_pred.csv` 是 **BF16 autocast** 下产生的。用同一批 checkpoint 重跑：

| 检查 | 结果 |
|---|---|
| FP32 两次独立运行 | max\|Δ\| = **0.0000**（可复现） |
| FP32 重跑 vs 已存 BF16 预测 | **12/12 个 run 都不同**，max\|Δ\| 0.31–1.12 个周期 |
| BF16 重跑 vs 已存 BF16 预测 | 8/12 逐位一致，其余差 0.0156–0.5 |
| j=0 单独成批 vs 已存文件（FP32 单批） | 逐位一致（说明差异来自精度与归约顺序，不是权重不匹配） |

结论：**BF16 autocast 跨进程不可逐位复现**，同一份权重重跑都会漂移，所以它不能作为冻结读出研究的基础。S1-B 全部改用 FP32（与当前协议一致），基准读数因此与历史文件不同，二者不混表。

## 2. 做了什么

对每个 (子集, seed)：

1. 重建冻结验证点：每台验证机 5 个截断点 `round(f·n)`，f = 0.40/0.55/0.70/0.85/0.95（`paper_b/configs/protocol.json`）。
2. 重建官方 TEST 末窗预测（每台机 1 个点）。
3. 额外重建 j = 1…9 的平移窗口：窗口结束点前移 j 个周期，其对参考时刻 RUL 的估计为 `pred_j − j`。

成员定义：

- 非多窗口变体：同一评价点上的 **3 个 seed** 的预测。
- 多窗口变体：3 个 seed × j ≤ J−1 的窗口，权重 `decay^j`；`pred ≥ 125` 的成员不参与（末窗始终保留）。

17 个变体：`mean` / `median` / `quantile q∈{0.5,0.4,0.3,0.2}` / `mean − k·sd, k∈{0.25,0.5,1.0,1.5}` / `nasa_bayes`（在 [0,125] 上网格搜索使 NASA 惩罚期望最小的点）/ 多窗口 `J∈{3,5,10} × decay∈{1.0,0.9}`。

## 4. 官方 TEST（选定之后计算，但**不是只算了一次**）

TEST：707 台机，每台 1 个预测。注意：每台机只有一个点，所以「逐机 RMSE」等于 |误差|，其均值等于 MAE；比较 RMSE 要看 pooled。

> **口径更正（两轮复核后）**：17 个变体的 TEST 数字**全部算过**，汇总表的 test 列就是这 17 次，所以「TEST 只评估一次」不成立。
>
> 第一版实现里 `evaluate()` 一次同时算 val 和 test，而它在选择循环内就被调用——**test 指标在选择定下来之前就已经算完了**，因此当时「test 列是事后补算的敏感性输出」这个说法是错的，脚本 docstring 与 JSON 里的 `selection_rule` 也一并错了。复核指出后已拆分：`evaluate_split(points, split)`，选择循环只算 val，`selected` 定下之后才对全部变体算 test。重跑后 17 行数值**逐列完全相同**（max\|Δ\| = 0），只有 `selection_rule` 的文本变了。
>
> 因此现在能成立的保证是「**选定值在计算 test 之前已经固定**」，而不是「test 只算了一次」。看过的次数就是 17 次，这一点如实记。

| | TEST pooled RMSE | TEST NASA sum | TEST MAE | TEST bias |
|---|---:|---:|---:|---:|
| mean（基线） | 10.9891 | 1773.5 | 7.2914 | **+0.663** |
| **multiwindow J5 decay0.9** | **10.7436** | **1580.8** | 7.3688 | **+0.065** |

选中的读出把 TEST 的系统性迟报从 **+0.66 压到 +0.07**，这是它降低 NASA 的主要机制；代价是 MAE 略升（7.29 → 7.37）——它换掉的是尾部，不是整体精度。

## 6. 必须一起报的四条限制

**① 验证集 NASA 不能预测 TEST NASA。** `nasa_bayes` 是验证集 NASA 最优的变体（13210.8），在 TEST 上却只降 0.32%；反之选中变体验证集 NASA 只排中游，TEST 反而最好。真正按 NASA 代价设计的那个变体没有迁移过去——这正是「风险感知读出」这个说法要小心的地方。

**② 10% 只超了 0.87 个百分点，且 FD001 变差。** 选中的本质是**时间平滑**（用前 5 个窗口加权平均、扣掉时间偏移），不是概率意义上的风险感知。它在 3/4 子集上改善 NASA，FD001 上 RMSE 和 NASA 都变差。

**③ 17 个变体里有 4 个同向过线，现象稳、确证性弱。** 过线门槛是均值基线的 90%，即 TEST NASA ≤ 1596.15。同向过线的是：

| 变体 | TEST NASA | 相对基线 |
|---|---:|---|
| multiwindow J10 decay0.9 | 1534.46 | −13.48% |
| multiwindow J10 decay1.0 | 1536.71 | −13.35% |
| multiwindow J5 decay1.0 | 1570.90 | −11.43% |
| multiwindow J5 decay0.9（选中） | 1580.76 | −10.87% |

四条全是 J ≥ 5 的多窗口；J3 的两条都不过（1671.2 / 1668.1）。这说明**现象本身是稳的**（多窗口平滑确实压低 NASA），弱的是确证性——因为我们在 17 个已经见过 TEST 的变体里挑了一条，而 4 条都能过线。

**④ 第二条判据在 RMSE 改善时是空条件。** 「RMSE 变化不超过种子标准差」只在 RMSE **变差**时才起约束作用；选中变体的 RMSE 是下降的（−0.2455），这条自动满足。所以真正起作用的只有 NASA 那一条，判据的实际强度比字面看起来弱。

## 8. 精度发现：BF16 预测不可逐位复现（**影响 S1-C 的审计范围**）

这一条独立于读出结论，单独记录。

| 检查 | 结果 |
|---|---|
| FP32 两次独立运行 | max\|Δ\| = 0.0000 |
| FP32 重跑 vs 已存 BF16 预测（12 个 run） | **12/12 全部不同**，max\|Δ\| 0.31–1.12 个周期 |
| BF16 重跑 vs 已存 BF16 预测（同权重重跑） | 8/12 逐位一致，其余 0.0156–0.5 |

即：**同一份 checkpoint 重跑，历史 `val_pred.csv` / `test_pred.csv` 都无法保证逐位复现**；差别来自 BF16 autocast 的归约顺序，不是权重或数据不匹配（j=0 单批 FP32 推理与文件逐位一致可证）。

对审计的含义：

- S1-C 的 96 格重算结论**不受影响**——它比较的是同一份已存预测与台账的一致性（差 5.3e-15），而不是「重跑能否得到同一份预测」。
- 但**任何依赖「预测可逐位复现」的说法都必须撤回**：历史预测是某一精度路径下的一次产物，只能保证「同精度同批次内一致」，不能保证跨进程一致。
- 今后凡需要可复现的读数，一律 FP32 重跑并记录精度；历史 BF16 数字只作为历史记录引用，不参与新结论的数值比较。
