## 0. 三句话（先读这一节再引用任何数字）

**① 这 96 格不能回答任何关于 Cycle 的问题。** `paper_b/experiments/grids/ablation8.json` 实测：
**96 个条目、`use_cycle` 全为 `True`、`False` 出现 0 次**。网格里没有 cycle-off 臂，
所以它**不得**被用来回答 S1-A（Cycle 插件），也不得写成「Cycle 已验」。

该字段与 pooled 的差 ≤ 1.6e-11，与 engine-level 的差**单格最大 +5.3001**（32 个臂×子集均值最大 +4.816）。

与权威台账 `paper_b/results/a8_engine_level.csv::val_eng` 最大差 **5.33e-15**（96/96）。
所以**问题在字段名，不在数据**：A8 报告用的就是 engine-level，不受影响。

## 3. `val_engine_rmse` 是 pooled：证据与后果

### 3.1 证据

| 检验 | 结果 |
|---|---|
| 96 格中 `stored == pooled`（差 ≤ 1.6e-11） | **96/96** |
| 96 格中 `stored == engine` | **0/96** |
| 全库 265 个 run 里该字段的读数 | `pooled_label_capped` **265**，其余读数 **0** |
| 96 格中 `stored − engine` 的最大值（单格） | **+5.3001**（`A8_sa_L70`/FD004/s303：11.8701 → 17.1701） |

全库结论来自 `LEGACY_VAL_FIELDS.md`（由 `recompute_val.py` 生成，265 run）；96 格结论由本轮独立重算确认。

**这不是「加权不同」。** 每台机恰好 5 个验证窗口，所以池化与逐机等权对每台机的权重都是 1/E；
差别在聚合顺序：`sqrt(mean MSE)` 与 `mean sqrt(MSE)`。按 §6.3 的口径规则，前者是补充、后者是主指标。

**而且这个字段错了两层，不止一层**：它既不是 engine-level，也不对应「预测也裁到 125」的读法。
265 个 run 里 **196 个**至少有一个预测超过 125，这些 run 存的是**未裁预测的池化值**；
只有 69 个 run 因预测未超顶，两种读法才恰好相同。96 格里这种情况有 **70 格**。
所以「按字面取这个字段」的人拿到的既不是逐机口径，也不是 capped 口径。

**这就是这个字段真正的危险**：它不是把数字整体抬高一点，而是**把 `sa` 的唯一一条稳定结论抹平**

## 4. 这个网格能支撑什么、不能支撑什么

**能支撑**（本网格内，val engine-level）：

1. **MS/SA/HI 的主效应与交互**：`sa` 在 FD001–FD003 一致为负、FD004 反号；
   `hi` 在 FD004 为负；`ms` 主效应接近 0，但**在 FD004 与 `hi` 有交互**——
   `+ms` 12.226 对 base 11.806（更差），`ms+hi` 11.579 却是 FD004 最好的一格。
   所以「ms 有帮助 / ms 有害」两种说法都不成立，成立的是**「ms 在 FD004 需要 hi」**。
2. **精简 vs 完整**：`F_full_basic_hi1` 与 `F_single_proj_basic_hi1` 各 12 格、test 全。

**不能支撑**：

1. **Cycle 的任何结论**——96/96 `use_cycle=True`，无 off 臂。（§0①）
2. **跨骨干普适性**——8 臂的差异全在 `full` 骨干；`Selected`（`single_proj`）不在网格内。
3. **预算效应**——96 格全是 `ep40 / pat12 / span70`，没有 80ep 臂。
4. **test 侧种子离散度**——test 只有 seed 101。
5. **任何「模块更优」的论文主张**——FD001–FD003 上整个方法空间跨度约 2 个 RMSE，
   而 seed 离散度 0.2–0.9，效应落在噪声里。
