# 诊断划分规格（split 43）：选择干净 + 截断像 TEST

**状态**：草案，**未冻结**。冻结前不得启动任何训练。

## 0. 为什么需要它

`HEADROOM_DIAGNOSTIC.md` 的「RUL 75–100 桶 bias +5.94」是在**官方 TEST** 上看到的。
用 TEST 上观察到的现象去设计模块，就是拟合 TEST。所以必须在别的集合上复现。

但现有验证集有两个问题叠在一起：

1. **截断方式不像 TEST**。验证集每台机取寿命的 40/55/70/85/95%，最后一个截点永远剩约 5% 寿命
   （实测：`last-cut` 版的尾部桶 **n=0**）。而 TEST 是在寿命**任意处**截断，75–100 桶占 17–23%。
   所以这套协议**结构上测不到** TEST 那个总体。
2. **被选轮压制**。`best_ep` 是按验证机 engine-level RMSE 挑的，任何系统性偏差都会抬高验证 RMSE，
   于是选轮本身就在压制这个偏差。`audit_tail_probe.py` 的 P0 在 FD001 上得 **−0.87**（TEST 是 +7.75），
   有相当一部分可能是这一条造成的，而不是现象不存在。

**结论**：目前没有任何一个集合同时满足「模型没在上面选过轮」和「截断像 TEST」。这个规格就是为了造一个。

## 1. 结构性阻塞（必须先解决，否则建不出来）

`paper_b/training/data.py:89 split_units()` 是**严格两路**：

```python
rng = np.random.default_rng(split_seed + 20261020)
sh = rng.permutation(units)
n_val = max(1, int(round(units.size * val_frac)))
val = sorted(int(x) for x in sh[fold * n_val:(fold + 1) * n_val])
train = sorted(int(x) for x in units if int(x) not in set(val))
return train, val
```

没有第三路，也没有「这半只诊断、不参与选轮」的概念。所以「把验证机分成两半，一半选轮、一半只诊断」
**在现有代码里做不到**：诊断机只要在 `val` 里，就会被 `best_ep` 的选择看到。

## 2. 推荐方案：不改代码，改成「不选轮」

不用三路划分。改成**让选轮不发生**：

- 训练用 `split_seed=43`，`patience >= epochs`（**禁用早停**，训练长度固定）。
- 诊断用 **`last.pt`**，不用 `best.pt`。
- 诊断集用**整个 val 集合**（不需要砍一半）。

这样 `val` 从头到尾没有参与任何选择：既没触发早停，也没决定保存哪个 checkpoint。
于是它既是干净的诊断集，又保住了样本量。

**代价**：`last.pt` 不是选出来的那个模型，性能会略低于 `best.pt`。但这里要回答的是
「**未经过选择**的模型有没有系统性尾部偏差」，`last.pt` 恰好是正确对象，不是妥协。

**必须写进交付物**：诊断结论只适用于「固定 40 轮 + last.pt」这个协议，不能直接搬到 `best.pt` 上报的模型上。

## 3. 替代方案（若坚持三路划分）

需要改 `data.py`：给 `split_units` 加 `diag_frac`，从同一个 permutation 里切出 `diag`，
`prepare_train` 返回 `train/val/diag`，选轮只用 `val`。这会**改变新批次的 h8**，
且改动落在训练数据管道上——属于协议变更，需要单独授权。

### 4.2 抽样规则

对每个诊断机（寿命 L），给定目标 RUL `r`：

- 截断点 = `L - r`，即只喂到该周期；`r` 取 **cap 125**（模型的目标就是截断值）。
- `r` 的分配用**按桶分层 + 比例分配**：桶内目标台数 = `round(该桶占比 × 诊断机数)`，
  余数按桶占比从大到小补齐，保证合计恰好等于诊断机数。
- 每台机在桶内用**固定种子**的 RNG 取 `r`（整数，桶内均匀），`r` 必须满足 `1 <= r <= min(L, 125)`。
  若某台机 `L` 太小、落不进被分配的桶，则回退到它可达的最高桶，并在产物里记一行 `fallback`。
- **RNG 种子、桶分配表、每台机的 (unit, r, truncation_cycle) 三者必须在训练启动前落盘并哈希。**

### 4.3 样本量（必须先看这个再定判据）

诊断机数 = `round(0.2 × 子集机数)`：FD001 20、FD002 52、FD003 20、FD004 50。
按 TEST 的尾部占比，75–100 桶约有 **4 / 10 / 4 / 8** 台——**单子集尾部台数是个位数**。

所以判据不能按子集看绝对值：

- **主判据**：四子集**合并**后 75–100 桶 bias ≥ **+2.0**（合并后尾部约 26 台）。
- **方向判据**：四子集 bias 至少 **3/4 同号为正**。
- **不得**用单子集的 bias 数值下结论（个位数台数，一台机就能翻转）。

### 7.1 结论

1. **现象在独立划分上复现**：合并 +5.04、4/4 同号，与 TEST 的 +5.94 同量级。
   换划分（43）、换截断方式（TEST 式）、换模型（不参与选轮的最后一轮）都还在 → **不是拟合 TEST**。
2. **「选轮压制了偏差」这个假设被推翻**：`best_state` 比 `model` **高** 0.45，选轮没有压制，反而略微放大。
3. 旧协议上 FD001 反号（−0.87）的原因**是截断协议**——固定 40/55/70/85/95% 永远取不到
   「还剩 75–100 个周期」这一段（P0b 尾部 n=0 已证），不是选轮。

### 7.2 限制

- 单子集尾部 n = 3–9，**单子集数值不可单独下结论**；FD003 的 +9.58 由 3 台机决定。
  判据只看合并值与同号计数。
- 诊断集是 split 43 的验证机，模型仍在这批数据上训练（只是不参与选择），
  所以「选择干净」成立、「数据未见」不成立。要在完全未见的数据上验，只能靠 TEST，
  而 TEST 已经打开过一次。
