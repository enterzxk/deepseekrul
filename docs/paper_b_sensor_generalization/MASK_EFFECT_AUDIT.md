1. mask 之后该传感器通道的数值确实改变，且 raw / 偏差 / EMA **三路同步失效**；

`E1E2_AUDIT.md`（等全格落盘后出）。

## 三条前置条件的判定

1. **mask 后通道数值确实改变，三路同步失效** —— 成立。`_features` 之前就把
   `x` 与 `baseline` 在隐藏通道置零，因此 raw、`x-baseline`、causal EMA 三路同时为 0；
   EMA 递推的初值与每一步输入都是 0，不会从历史里把旧值带回来。梯度在隐藏通道上
   **精确为 0**，说明没有任何残留通路（残差、池化权重、注意力 Key/Value）能把它带进预测。
2. **噪声只在训练期** —— 成立。`add_noise` 只出现在 `train_one` 的训练循环里；
   `predict()` 没有 augmentor 参数，连跑两次逐位相同；补齐位不加噪、不改原地。
   评测侧的噪声压力是 `evaluation.py::eval_noise` 另起的固定扰动协议，用冻结的
   训练侧 σ 与固定噪声场，与训练期注入是两件事，不共用随机流。
3. **配对性** —— 成立。构造 augmentor 不消耗全局 RNG，同 seed 下 E0 与 E1/E2
   的初始化哈希相同（`7cf9a8c0e58e60f8`）；mask 的均匀流按 `700000+seed` 独立播种，
   p=0.20 是 p=0.10 的严格超集，两臂嵌套可比。

## 两条给执行侧的操作提醒

1. **不要把 debug 开关加进 `scripts/run_sensor_aug.py`。** 该文件在 h8 指纹列表里，
   加一个 `--dump-mask` 参数就会把 h8 从 `515eb76fc396` 改掉，E0 与 E1/E2 的代码身份
   随即分裂——正是这轮一开始要避免的事。需要 dump 时用
   `scripts/audit_mask_effect.py`（不在指纹列表，h8 保持 `515eb76fc396`，已实测确认）。
2. **选轮口径与主口径不是同一个聚合。** `train_one` 用 `engine_equal`
   （`sqrt(mean_u MSE_u)`，与 pooled 恒等）选 checkpoint，而主指标是
   `mean_u sqrt(MSE_u)`。设计均衡（每机恰好 5 个截点）时 pooled == engine_equal 精确成立，
   但 mean-of-roots 是另一种聚合，选出的轮次不必是主口径最优。这是继承自冻结协议的做法，
   **本轮不改**，但报告里要写明「选轮用 engine_equal、主指标事后从预测重算」。

## 边界

- 只核了 FD001 与 FD004 两个子集；FD002/FD003 走同一条代码路径，未单独跑。

- A2c 的 Δpred 是**同一批验证窗**上 mask 前后之差，不是泛化误差的变化。
