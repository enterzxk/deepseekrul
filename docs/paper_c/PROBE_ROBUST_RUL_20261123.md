# 鲁棒 RUL 方向的可行性探针（2026-11-23）

> 对象：外部 v2 计划《部分可观测与传感器故障下的跨架构鲁棒 RUL 预测》。
> 方法：**零新训练**，直接用已训好的 A 段 30 格 checkpoint 做两个探针。
> 结论：**前提成立（损伤很大），但计划的基线选错了，预期收益被高估约一个量级。**

---

## 0. 三个数

1. **损伤是真的**：dropout 40% 让 V0 从 11–14 掉到 **32.5–52.6**（+19 到 +40）；
   stuck 4 通道 +12.5 到 +30.3。远高于计划设的 2.5 门。
2. **但一个闭式跨通道 ridge 就修回 47%–108%（中位 ~87%）**，不需要任何神经网络。
3. **真正剩下的空间只有 +0.02 到 +12.8 RMSE**，且集中在 `dropout40` 与 `stuck4`；
   `dropout20` 与 `stuck2` 上 ridge 基本已经做完了。

---

## 1. 探针 A：故障到底造成多大损伤

注入方式（只作用于验证窗，模型与权重不动）：

- **dropout**：按发动机固定选 3/14（20%）或 6/14（40%）通道，从窗口中点起置 0
  （输入已标准化，0 = 该通道均值，等价于均值填补）；
- **stuck**：按发动机固定选 2/4 通道，从 `t0 = round(0.4·(L−1))` 起冻结为该时刻的值。

指标：逐发动机 RMSE 再平均（与主协议同口径）。

## 2. 探针 B：简单修复能做到多少（这才是关键）

四种修复，全部只改输入、不训练：

- `hold`：故障通道冻结在最后一个观测值（≈ 计划的 `R5b`）；
- `chanmean`：故障通道用自身窗口内观测部分的均值（≈ 计划的 `R5m` 一类）；
- **`ridge`：跨通道线性重构**，`x̂_c(t) = Σ_{j≠c} w_j·x_j(t) + b_c`，
  权重在**干净训练窗**上用闭式解拟合（α=1.0，未调参）。这是「利用跨传感器物理冗余」的**最朴素实现**。

`ridge_gain = ridge − raw`（负 = 修复有效）。

**三条读法**：

1. `hold` 与 `chanmean` 这两种「计划里的公平基线」**几乎没用，甚至有害**
   （`ffve/FD001` dropout40：raw 40.11 → hold 53.75，更差）。
   所以「打赢 R5m」这个门没有信息量——一个线性最小二乘就能赢它一大截。
2. **ridge 回收了绝大部分损伤**。计划预期的「重构增益 Δ ≥ +2.0 ~ +6.0」，
   如果拿 V0 当基线，实测是 **+6 到 +30**，严重低估；
   如果拿 ridge 当基线，实测只剩 **+0.02 到 +12.8**，又变成高估。
3. **真正的机会在残差里**，而且分布很不均匀：

| 条件 | ridge 修复后的残差（相对 clean） | 还有没有空间 |
|---|---|---|
| dropout 20% | +0.02 到 +1.50（个别 −0.13） | **基本没有** |
| stuck 2 通道 | +0.02 到 +0.83 | **基本没有** |
| stuck 4 通道 | +0.49 到 +4.95 | 中等 |
| dropout 40% | +1.49 到 +12.77 | **大**（尤其 FD004） |

## 3. 这对计划意味着什么

### 3.1 必须改的三处

1. **基线换成 ridge（以及一个同容量 MLP 填补器）**，不是 V0 / R5m。
   现计划的 `Gate 1-Pilot` 写「相对 V0 与 V0+R5m 恢复 ≥ +1.5 RMSE」——
   **这一条 ridge 单独就能过**，所以它不能用来证明模块有效。
2. **门改成「相对 ridge 的残差增益」**：`Δ_vs_ridge ≥ +1.5 RMSE`，
   且只在 `dropout40` / `stuck4` 上要求（另外两种条件已经没空间了，要求它反而是自欺）。
3. **预期效应量重写**：不是「+2.0~+6.0 vs V0」，而是
   「**在 dropout40 上，相对 ridge 再降 1.5–4 RMSE**」——这是可辩护的、也是可证伪的。

### 3.2 计划里做对了、要保留的

- 换任务（从饱和的 clean 精度换到故障鲁棒）——**这是本轮最有价值的一步**，
  因为损伤是实测的 +19 到 +40，不是猜的；
- 先做零训练探针再定门——正是上轮教训的正确落地；
- 内置置换对照（`CS-MRG-Permuted`）——保留，但要放在「vs ridge」之后作第二道；
- 对称分档（Clean-NonHarm / Dropout / Stuck / Universal）——保留。

### 3.3 仍然没解决的一件事

`CS-MRG` 的信息论证在**故障场景下是成立的**（这一点与 CADF 不同，我要说清）：
故障通道的信息**确实不在输入里**，模块做的是「用观测通道估计它」，
这是**修复**而不是**重编码**。所以上一轮那条「不引入新信息」的否决**不适用于这里**。

但由此产生一个更严格的要求：**修复质量的上限由跨通道冗余决定**，
而 ridge 已经吃掉了这块冗余的大部分。所以模块的贡献只能来自
「非线性/工况条件化的冗余关系」，而且必须**显式证明它超过了线性基线**。

---

## 4. 限制（不能忽略）

1. **故障是合成的**：置 0 = 均值填补，stuck 起点固定 0.4L，通道选择按发动机固定。
   真实传感器故障的统计特性不同，幅度会变，但量级不会差一个数量级。
2. **只跑了 seed 101**：单 seed 的绝对值会动，但「ridge 回收 47%–108%」这个量级不会翻。
3. **ridge 的 α 没调**：调了只会更好，也就是**门槛只会更高**，不会更低。
4. **只测了「修复输入」这一条路**：没有测「训练期就做随机丢弃增强」这条更强的基线
   （让骨干自己学会容忍缺失）。**这条基线必须在正式实验里，否则模块的增益可能只是
   「骨干从没见过损坏」**。
