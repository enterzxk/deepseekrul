## 0. 结论先行

1. **方法空间已经饱和。** 七个分布型方法（1 到 66 参数，高斯到经验形状）在 12 个实例上的平均 CRPS 落在 5.67–6.24，最优与次优相差 0.01。除"密度网格"这一错误形式外，**没有任何方法统计上优于任何其他方法**。66 参数不敌 4 参数。
2. **删失修正的收益是真实的，但比 v1 报告的小得多。** 真 CRPS 下 `cens − trunc = +0.47`，9/12 实例的配对 bootstrap CI 排除 0（换成 v1 的 $\mathbb{E}|X-y|$ 度量则是 +1.45、12/12）。删失读法必须保留，但它不是卖点。
3. **真正的缺陷在条件覆盖，而不在边际覆盖。** 名义 90% 区间在边际上达到 92.1%，按真实 RUL 分箱则是 83.0%–96.5%，分箱偏差从 −5.9 到 +7.7 周期。$[75,100)$ 段是**同时欠覆盖且高估**——最危险的那种组合。
4. **该缺陷不能由任何"只吃点预测"的校准器消除**，这与容量、目标函数都无关：MSE 最优的单调映射让最差分箱偏差从 5.80 变到 6.84（变差），向均值收缩让它单调升到 70.94，只有允许读取真实分箱的 oracle 才能归零。机制是 $\hat y$ 切不开分箱：真实 RUL 在 $[75,100)$ 的发动机，其预测横跨 32–124 周期。
5. **v1 报告里"CRUDE 在 12/12 实例上最好"是评测假象。** 原因是每个经验型方法都被强行套用了 EMOS 的宽度乘子，实测覆盖率只有 0.892 而不是 0.90，而 CRPS 奖励锐度。给它们各自的 dev 调宽后，CRUDE 从第 1 掉到第 5（真 CRPS）或第 4（$\mathbb{E}|X-y|$）。

## 1. 先修一个指标名实不符的问题

早期表格里的"CRPS"实际算的是 $\sum_k|F_k-\mathbb 1[y\le k]|$。对整数支撑分布，该式恒等于 $\mathbb E|X-y|$，**不是 CRPS**——真 CRPS 还要减去锐度项 $\tfrac12\mathbb E|X-X'|=\sum_k F_k(1-F_k)$。

这一项与 $y$ 无关但**随方法变化**，因此：

- 它不破坏同一方法内部的一致性；
- 它**会改变方法之间的排序**，且系统性地偏袒窄分布；
- 它让数字与已发表 C-MAPSS CRPS 不可比（本表数值约为旧值的一半）。

`v2_compare.py` 现同时输出 `crps`（真 CRPS）与 `crps_l1`（旧的 $\mathbb E|X-y|$），下表两列并列，旧结论可用后者核对。**主表一律用真 CRPS。**

## 2. 协议：本轮与上轮的唯一实质差别

| 项 | v1 / 上轮 | v2（本轮） |
|---|---|---|
| dev 样本 | 各方法各自装配 | **四舰队 dev 合并 709 台，全方法共用** |
| 宽度 | 部分方法沿用 EMOS 的乘子 | **每个方法各自的乘子，在交叉拟合 dev 上校准到 0.90** |
| 测试集用途 | 曾用于把宽度加宽到实测 0.90 再比 CRPS | **只看一次，不参与任何选择** |
| CRPS 定义 | $\mathbb E\|X-y\|$ | 真 CRPS（并保留旧量） |
| 方法数 | 12 | 13（新增 `crude_km`） |

新增的 `crude_km` 值得单独说明：CRUDE 用标准化残差的经验分布做形状，但 C-MAPSS 的 dev 里 27.9% 的标签是 125，直接塞进经验 CDF 会在封顶点制造一个占两成质量的伪尖峰。`crude_km` 改用 Kaplan–Meier 估计该残差分布，把封顶样本当作右删失（进风险集、不算事件），尾部的平台自然成为原子。**这是"把 CRUDE 用对"，不是新方法。**

## 6. T5 条件覆盖：本轮最重要的表

`cens` 在 12 个实例上池化，按真实 RUL 分箱（名义 90%）：

| 分箱 | 发动机数 | 覆盖率 | Wilson 95% CI | 平均偏差（预测−真值） | 偏差范围 |
|---|---:|---:|---|---:|---|
| [0,25) | 423 | 0.920 | [0.890, 0.942] | +3.45 | [+1.91, +5.02] |
| [25,50) | 252 | 0.929 | [0.890, 0.954] | +0.69 | [−0.82, +2.71] |
| [50,75) | 270 | **0.830** | [0.780, 0.870] | +4.01 | [−2.14, +10.04] |
| [75,100) | 378 | **0.865** | [0.827, 0.896] | **+7.66** | [+2.96, +13.82] |
| [100,126) | 636 | **0.965** | [0.948, 0.977] | **−5.86** | [−7.88, −3.39] |

边际覆盖率 0.921，看起来达标。分箱之后：

- $[50,75)$ 与 $[75,100)$ **欠覆盖**（0.830 / 0.865），Wilson 区间明确排除 0.90；
- $[100,126)$ **过覆盖**（0.965），区间过宽；
- $[75,100)$ 同时**高估 7.7 周期**。这正是维修决策最关心的区间：告诉你还有 90 个周期，实际只剩 82 个。
- 三种骨干、四个舰队**全部同向**（偏差范围列的最窄区间是 $[+2.96,+13.82]$，不含 0）。

**两个分箱的偏差性质不同，不能混为一谈。**

- $[75,100)$ 段**封顶样本比例为 0**（12 个实例全部为 0.00，见 `identifiability.json` 的 `p_capped` 列）。
  该段的高估**与 125 封顶约定无关**，不能用"标签被截断"解释掉。它是纯粹的条件偏差。
- $[100,126)$ 段的 −5.9 周期**是封顶约定的直接后果，不是缺陷**：该段 32%–60% 的样本真实 RUL 超过 125，
  标签被写成 125，而模型的支撑止于 125，均值必然低于 125。该段过覆盖（0.965）也与此一致——
  区间把 125 包住了。

因此**本文的核心缺陷是 $[75,100)$ 的 +7.7，而不是 $[100,126)$ 的 −5.9。** 后者选错了靶子。

**只报边际 PICP 的论文会在这个缺陷上完全失明。** 这不是修辞：0.921 与名义 0.90 只差 0.021，任何"接近名义值"的判据都会通过。

## 7. 为什么重校准修不掉：三重证据

命题与证明形状见 `CALIBRATION_MATH_SPEC.md` §4。这里只放实测。

**7.1 MSE 最优的映射让偏差变差.** 等渗回归 $g^\star=\mathbb E[Y\mid\hat y]$ 是所有 $\hat y$ 的可测函数里平方误差最小的。

关键是要在 **test 本身上**拟合，否则会把 dev→test 漂移误当成"映射不对"。给映射器直接看测试集后（A 臂）：

| 映射 | RMSE | 最差分箱偏差 | 五个分箱偏差 |
|---|---:|---:|---|
| 骨干原样 | 11.61 | 5.80 | — |
| 等渗（dev 拟合） | 11.76 | 6.84 | 2.7 / 1.7 / 5.0 / 4.6 / −6.8 |
| **等渗（test 内拟合）** | 10.96 | **6.53** | 1.1 / 1.1 / 5.6 / 5.0 / −6.5 |
| 逐分箱 oracle（不可实现） | 10.60 | 0.00 | 0 / 0 / 0 / 0 / 0 |

三骨干的 test 内拟合等渗最差分箱偏差为 **6.53 / 7.18 / 6.39**。
即便取该函数类的 MSE 最优解、且不欠任何分布漂移，$\pm6.5$ 周期仍在那里。
**MSE 最优与消除分箱偏差是两个不同的泛函。**

**7.2 收缩单调恶化.** 对 $g_t(\hat y)=\hat y+t(\bar y-\hat y)$，最差分箱偏差随 $t$ 从 0 到 1 单调上升 5.80 → 70.94。偏差不是"向均值回归"造成的假象。

**7.3 只有 oracle 能归零.** 允许逐分箱最优平移（即允许读真实标签）时，最差分箱偏差降到 0，RMSE 由 11.61 降到 10.60。这说明偏差**真实存在且有害**（修掉它连点预测都变好），但分箱归属在预测时不可观测。

**7.4 机制.** `diag_identifiability.py`：真实 RUL 在 $[75,100)$ 的发动机，其 $\hat y$ 从 32 跨到 124（A 臂 FD004）；给定 $\hat y\in[80,90)$ 时 $Y$ 的标准差仍达总体标准差的 0.36 倍。**预测值不是分箱的充分统计量**，所以任何 $\hat y$ 的函数都无法只作用于某个分箱。

**7.5 dev 上也修不掉.** `diag_band_shift.py`：$[75,100)$ 段骨干在 **dev 上**就高估 +8.1 到 +13.0，校准层在 dev 上把它改到 +9.1 到 +9.9（合并样本），即**层在训练样本上就把这个偏差放大了**。这不是过拟合或迁移问题，是目标函数与泛函不匹配。

**结论.** 任何声称"加一个校准层改善 C-MAPSS 条件覆盖"的工作，必须出示 §7.1–7.4 这组证据说明其改进不来自测试标签泄露。否则改进只可能来自那里。

## 8. 评测协议的自证陷阱（对领域的直接警告）

把每个方法的宽度加宽到**测试集实测覆盖率 = 0.90** 再比较 CRPS，是常见做法，也是自证：
它等价于以测试标签为监督，给每个方法单独做了一次校准。

实测后果（同一批 pmf，只换宽度选择规则）：

| 方法 | 宽度=各自 dev 校准（合法） | 宽度=测试集加宽到 0.90（自证） |
|---|---|---|
| CRUDE, cap as exact | 5.78（第 5） | 10.19（旧度量下第 1） |
| censored MLP | 5.77（第 3） | 10.97 |

加宽倍数 1.15–1.60：**离 0.90 越远的方法，被加宽得越多，因而获益越大。** 这个规则会系统性地奖励过度自信的方法。本轮结论 5 就是移除这条规则后的直接结果。

## 11. 对论文决策的直接含义

- **不能**写成"提出一种新的概率校准方法"。七个方法统计上不可区分，且更简单的形式更好。
- **不能**写成"本方法在 C-MAPSS 上取得更优 CRPS"。没有更优。
- **可以**写成一篇关于**条件覆盖为何无法通过事后重校准修复**的测量/协议论文，其核心证据是 §6 + §7，且该证据在三种骨干、四个舰队上一致，不依赖于本层是否优秀。
- 该论文的必要条件：独立数据上复现同一现象（第四阶段）。
