# 事后重标定为什么修不好 RUL 的不确定性

**结论先行**：在这一轮我系统性地试了 **8 个重标定族**（1–4 参数，3 种拟合目标），全部在 dev 上拟合、在 test 上评估。**0/8 优于"什么都不做"**。原因不是方法不够好，而是**校准集与部署集不可交换**——这是协议级的缺陷，任何在 dev 上拟合的矫正都会被系统性放大。

同时给出一条正面的诊断：**模型自报的"90% 区间"实际只覆盖 0.79–0.86，真实过度自信 0.07–0.15**，比文献里任何方法间差异大 3 倍以上，而标准 PICP 表把它掩盖了。

## 2. 根因：校准集与部署集不可交换

同一条流水线上，dev 与 test 的三组两样本检验：

| 子集 | n_dev | n_test | RUL 均值 dev | RUL 均值 test | KS(ŷ) p | KS(\|误差\|) p | CvM dev | CvM test | 比值 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| FD001 | 300 | 93 | 78.9 | 71.5 | 0.0080 | 0.2725 | 1.987 | 0.253 | **7.9×** |
| FD002 | 780 | 235 | 80.7 | 69.1 | 0.0000 | 0.0018 | 9.088 | 2.061 | **4.4×** |
| FD003 | 300 | 97 | 85.8 | 72.2 | 0.0047 | 0.1007 | 14.889 | 0.358 | **41.6×** |
| FD004 | 747 | 228 | 89.2 | 73.8 | 0.0000 | 0.1714 | 19.379 | 2.304 | **8.4×** |

三件事同时成立：

1. **预测分布漂移**：KS(ŷ) 在 4/4 子集显著（p ≤ 0.008）。dev 的平均预测比 test 高 **7.4–15.4** 个 RUL 单位。
2. **误差幅度基本不漂**：KS(|误差|) 在 3/4 子集不显著（p = 0.27/0.10/0.17），只有 FD002 显著。所以这是**协变量漂移**，不是模型质量差。
3. **校准状态差 4.4–41.6 倍**：dev 的 PIT CvM 是 test 的 4.4–41.6 倍。

第 3 条直接决定 §1 的结果：在 dev 上最小化 CvM 会选出一个"为更差标定而设计"的矫正，搬到 test 上必然过度矫正。表 2 的 `scale_cvm` 就是例子——它把 cov@90 从 0.845 推到 0.921，同时在 50% 上从 0.55 推到 0.79（名义 0.50），CRPS 涨 24%。

**一个标量尺度只能校准一个名义水平。** 这是 §1 里所有单参数族失败的直接原因：修好 90% 必然毁掉 50%。

## 3. 度量本身有问题：整数端点把 PICP 抬高了

同一批预测、同一批标签，两种覆盖定义：

- **整数区间**（文献用法）：`[lo, hi]`，`lo = min{k : F(k) ≥ α/2}`，`hi = min{k : F(k) ≥ 1−α/2}`
- **随机化覆盖**（离散分布的正确定义）：`u* = F(y−1) + U·p(y)`，`U ~ Unif(0,1)`，覆盖 = `P(α/2 ≤ u* ≤ 1−α/2)`

| 子集 | 50 整数 | 50 随机 | 抬高 | 90 整数 | 90 随机 | 抬高 |
|---|---:|---:|---:|---:|---:|---:|
| FD001 | 0.667 | 0.595 | +0.071 | 0.871 | 0.850 | +0.021 |
| FD002 | 0.596 | 0.489 | +0.107 | 0.881 | 0.857 | +0.024 |
| FD003 | 0.629 | 0.517 | +0.112 | 0.804 | 0.790 | +0.014 |
| FD004 | 0.548 | 0.429 | +0.119 | 0.825 | 0.800 | +0.024 |

整数端点约定把 PICP 系统性抬高 **0.014–0.024（90% 水平）** 和 **0.071–0.119（50% 水平）**。抬高量由网格上端点 bin 的质量决定，与模型无关——125 处的原子占 17%，中心区 bin 质量 0.05–0.10。

后果：**两个模型在同一张 PICP 表上的差（通常 0.01–0.03）小于这个约定的偏移量**。所以文献里"我的 PICP 更高"这个比较在 90% 水平上处于噪声地板以下。

这也是 §1 里 ORACLE 失败的原因：ECDF 重映射把 PIT 均匀性改善 3.8 倍（CvM 1.244 → 0.324），但整数区间覆盖从 0.845 升到 0.954——**整数区间覆盖不是分布标定的单调函数**。用它做目标，会把已经正确的矫正判为错误。

## 4. 正面诊断：真实的过度自信是 0.07–0.15

模型自报的区间概率含量（它自己声称的覆盖）与实测：

| 子集 | 声称（90% 区间） | 实测整数 | 实测随机 | 过度自信 |
|---|---:|---:|---:|---:|
| FD001 | 0.929 | 0.871 | 0.850 | 0.079 |
| FD002 | 0.935 | 0.881 | 0.857 | 0.078 |
| FD003 | 0.931 | 0.804 | 0.790 | 0.141 |
| FD004 | 0.933 | 0.825 | 0.800 | 0.133 |

"90% 区间"实际是 79–86% 区间。这个差距是**任何**方法间差异（0.01–0.03 PICP、0.02–0.06 CRPS）的 3–5 倍，而且它是模型的绝对属性，不是排序问题。

## 5. 方法学结论

1. **不能靠在 dev 上拟合重标定来修复。** dev 与部署集在预测分布上显著不同（KS p ≤ 0.008）、在标定状态上差 4.4–41.6 倍。任何 dev 拟合的矫正都会被放大，0/8 通过。
2. **结构上的出路是让校准集与部署模型同质量。** 标准做法里 dev 用的是 K 折 OOF 预测（每折只见过 80% 数据），而部署用的是全量模型——两者的误差分布本来就不一致。要么部署 K 折集成（让二者重合），要么把矫正强度按估计的质量差收缩。前者是 CV+ / jackknife+ 的构造，后者需要 test 侧标签，当前协议下不可得。
3. **报告必须改口径。** PICP 需注明是整数端点还是随机化定义（差 0.02–0.12），并同时报"声称概率含量 vs 实测覆盖"。只用整数 PICP，方法间比较落在约定偏移以下。
4. **单参数尺度不能用于多水平校准。** 它只能校准一个水平。要同时校准 50/80/90/95，至少需要形状自由度，而形状自由度在 n=93–235 上不可估（这正是上一篇审计的结论：每箱需 143 台）。
