## 1. 一句话结论

**在 FD002 的开发划分上，M4（条件匹配收缩参考 + 6 维证据门控）相对同特征强 Transformer（M0）的 matched-cutoff RMSE 点估计低 1.98，但发动机聚类 95% CI 为 [−4.05, +0.29]，跨零；晚报风险没有同步改善（severe-late 0.250 vs 0.218，更差）；Protocol B 下 late_fraction 均值 0.521，压线超过 0.52 门禁。** 因此当前证据只能支持“方向性、不确定的误差收益”，**不能**支持“显著优于基线”或“安全收益”。

读法：

- 重复性核对：`M4c_noid` 与 `M4_racdr` 在 3 个种子上 `matched_cutoff_rmse` / `best_val_rmse` **逐位相同**（14.962552/12.543752 等），证实它是配置重复而非消融，已排除出证据表。

## 5. 解释与限制

1. **主指标不显著**：matched 与 Protocol C 的所有比较 CI 都跨零。只有 Protocol B（相对基线的提前截断协议）显著，不能替代主指标。
2. **增益无法归因于门控**：M4 − M3 在所有协议下都不显著（P≈0.93–0.96），说明“证据门控”相对“仅收缩参考”的增量没有被数据分辨出来。
3. **安全叙事不成立**：matched severe-late 更差；Protocol B late 均值超门禁。late-weighted loss（1.8）没有带来晚报改善。
4. **代码版本缺口（硬限制）**：这 12 个 FD002 单元由 `run_candidate.py` SHA256 `6715b40…` 产生，该源码已被覆盖为 `c0bdf27…`，GitHub main 为第三个版本；**没有可复现的代码快照**。本报告的数字可复算（CSV 在），但“重跑得到同样结果”当前不成立。
5. **样本量**：FD002 开发划分 52 台发动机、3 个模型种子（M4b 已补齐 3 个种子）。CI 已按发动机聚类，但 52 台仍是小样本。
6. **协议定义**：matched-cutoff 是每台发动机在 `U[40, 0.95·观测寿命]` 上的一个随机点（seed 2026，跨模型一致），不是“统一截断”；Protocol B 是寿命比例截断；Protocol C 是绝对剩余寿命网格（跳过已失效点）。
7. **未完成**：FD001 全部崩溃（代码 bug），M1_global 全崩溃；因此本报告只覆盖 FD002，**不能**外推到 FD001 或官方 test。

### 7.5 诚实限制（必须与结果同时报告）

1. **FD001 的 matched/Protocol C 区间跨零**：方向为正（−1.16/−1.01）但不显著；只有 Protocol B 显著。FD002 三个协议都显著。
2. **tf 基线早停偏早**：FD002 三个种子的 `best_epoch` 为 5/6/2（patience=10），即验证 RMSE 在极早期就达到最低；这使 tf 基线可能被低估。该早停行为在开发划分上也存在（M0 best_epoch 3/3/5），不是本次新引入，但会放大候选优势。要在下一阶段用更长 patience 或固定 epoch 复核。
3. **不是独立盲测**：`split_seed=2027` 与开发 `split_seed=7` 的验证发动机重合 FD001 7/20、FD002 6/52；代码与超参在 split 7 上选定。
4. **n=3 seeds / 20 与 52 台发动机**：CI 已按发动机聚类，但样本仍小。
5. **这是唯一一次预登记复验**：结果不得用于回改候选或再调超参；后续若改模型，必须重新预登记。
