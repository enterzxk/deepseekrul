## 2. 结构创新设计

### 2.1 出发点：现有负结果的可解释性

V3 的九个干预全部失败，但**它们都是在「无早停、取末轮」的冻结协议下测的**——该协议系统性惩罚容量。

因此 V4 的第一个动作是：**在正确协议（验证集早停）下重测容量**。
若容量在正确协议下转为正收益，则结构创新有了立足点。

### 2.2 候选架构：双流多尺度 Patch Transformer（Dual-Span Patch Transformer, DSPT）

```
输入：发动机在时刻 t 的全部可用历史
        │
        ├─ 流 A（短跨度）：50 循环窗口 → patch 长度 10 → 5 个 token
        │
        ├─ 流 B（长跨度）：100 循环窗口 → patch 长度 25 → 4 个 token
        │        （t<100 时左侧 padding，并用 mask 屏蔽）
        │
        ├─ 工况路由：由 op_1..3 产生 6 维软权重，调制两流的 token
        │
        ├─ 跨流融合：门控（gate）由可观测证据产生（覆盖度、年龄、抖动）
        │
        └─ 退化 token：一个可学习 token 聚合全序列，监督信号 = 寿命分数
```

**三个模块的出处与改进**：

| 模块 | 出处 | 本工作的改进 |
|---|---|---|
| Patch 化 token | PatchTST (ICLR 2023) | 双尺度并行，而非单尺度 |
| 工况路由 | MoE / Qu et al. 2026 | 软路由 + 可观测证据门控，参数量 <5k |
| 双流融合 | 本工作的观测跨度发现 | 把「两个模型 + 硬路由」变成「一个模型 + 软融合」 |

**核心论点**：观测跨度不是要选一个，而是**两个尺度携带互补信息**。
V3 的硬路由证明了这一点（t≥100 后 w100 更好 2.9 个循环），但硬路由丢弃了短流的信息。
软融合应当严格优于硬路由。

### 2.3 备选架构（若 DSPT 不work）

- **DSPT-lite**：去掉工况路由，只保留双流 + 门控（参数 +8k）
- **退化 token 监督**：加一个辅助头预测寿命分数（多任务），参数量不变

## 3. 实验计划

### 阶段 1：协议校准（1 天）

1. 在正确协议（早停）下重测容量：d64/1层、d64/2层、d96/2层、d128/2层
2. 确认容量是否转为正收益
3. 确定 DSPT 的宽度与深度

### 阶段 2：DSPT 实现与筛选（2 天）

1. 实现 DSPT（新文件 `src/candidates/dspt.py`，不改现有代码）
2. 单折筛选：DSPT vs PE，FD002 f0
3. 若正向，铺 5 折 × 3 种子

### 阶段 3：全矩阵（3 天）

1. 四子集 × 5 折 × 3 种子 = 60 个模型
2. 官方测试集成评估
3. 与 STAR / SA-MSTCN-GFA 对照

### 阶段 4：消融与写作（2 天）

1. 消融：去双流、去路由、去门控、去退化 token
2. 协议敏感性（Idea A）作为稳健性章节
3. 论文写作

## 4. 验收标准

| 编号 | 条件 | 判据 |
|---|---|---|
| V4-A | 四子集 RMSE | 全部 ≤ 目标线（10.4/13.0/10.4/13.5） |

| V4-C | 跨主干 | DSPT 的增益在 BiLSTM/TCN 上也成立（或明确说明是架构特异） |
| V4-D | 统计 | 3 种子 × 5 折，报告种子间方差与发动机聚类区间 |
| V4-E | 可复现 | 完整配置、种子、脚本、预测 CSV |

## 5. 风险

| 风险 | 概率 | 缓解 |
|---|---|---|
| DSPT 不优于 PE | 40% | 退回 DSPT-lite 或纯双流 |
| 容量在正确协议下仍无效 | 50% | 结构创新改为「效率」导向（同精度更少参数） |
| 无法超过 STAR | 25% | 目标线下调，但必须超过至少两篇 |
| 时间不够 | 30% | 优先 FD002/FD004（六工况，最难也最有说服力） |

## 6. 与 V3 成果的关系

V3 的观测跨度发现**不丢弃**，而是转化为 DSPT 的双流设计。
V3 的九个负结果**不丢弃**，而是作为「为什么需要正确协议」的证据写进论文。
V3 的协议敏感性分析（Idea A）作为稳健性章节。
